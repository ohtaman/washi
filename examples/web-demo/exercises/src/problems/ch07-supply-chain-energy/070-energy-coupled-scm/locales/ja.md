# #070. 電力料金・蓄電池連携型ロットサイズ総合計画

<!-- section:scenario -->
製造工場において、1 時間単位の複数期間（電力 kW がそのまま 1 時間あたりの電力量 kWh に一致）にわたり、単一品目のロットサイズ生産計画と時間帯別電気料金（TOU）・ピークデマンド料金・構内蓄電池を含む電力運用を同時に最適化します。

- **生産と在庫**: 製品在庫ゼロから出発し、ある期に生産を行うと固定段取り費が発生してライン能力上限まで連続生産できます。各期の製品需要を満たしつつ、余剰製品は 1 単位・1 期あたりの保管費を払って翌期へ繰り越せます。
- **電力結合と系統買電電力**: 工場の総電力需要は「基礎負荷 ＋ 稼働期の固定待機電力 ＋ 生産量に応じた加工電力」となります。系統買電電力は工場の総電力需要に充電を加えて放電を差し引いた値（逆潮流なしの非負）となり、全期間の最大系統買電電力にピークデマンド料金が課金されます。
- **蓄電池運用**: 初期蓄電残量（SOC）から始まる蓄電池は定格電力上限以内で充電または放電（同時充放電不可）を行い、充放電効率を伴いながら 0 から蓄電池容量上限までの範囲で推移し、最終期末には初期蓄電残量（SOC）以上へ戻す必要があります。

生産段取り・生産量・製品在庫・蓄電池運用を同時決定し、**生産・在庫・電力・デマンド料金の総コストを最小化** してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `demands` | `number[]` | 各期の製品需要量（単位） |
| `setupCost` | `number` | 生産稼働 1 回あたりの固定段取り費 |
| `holdCost` | `number` | 期末製品在庫 1 単位・1 期あたり保管費 |
| `prodCap` | `number` | 1 期あたりの最大生産能力（単位） |
| `setupPower` | `number` | 稼働期の固定待機電力（kW） |
| `unitPower` | `number` | 製品 1 単位生産あたりの加工電力（kW/単位） |
| `baseLoads` | `number[]` | 各 1 時間期間の非生産系工場基礎電力負荷（kW） |
| `prices` | `number[]` | 各期の時間帯別電気料金単価（1 kWh あたり） |
| `demandCharge` | `number` | 期間全体の最大系統買電電力に対するデマンド単価（1 kW あたり） |
| `batteryCap` | `number` | 蓄電池容量上限（kWh、下限は 0） |
| `initSoc` | `number` | 初期蓄電残量（SOC、kWh、最終期末の下限も兼ねる） |
| `maxPower` | `number` | 1 期あたりの蓄電池最大充放電電力（kW） |
| `etaCharge` | `number` | 充電効率（(0, 1] の範囲） |
| `etaDischarge` | `number` | 放電効率（(0, 1] の範囲） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `setups` | `number[]` | 各期の生産段取り有無（0 または 1） |
| `production` | `number[]` | 各期の非負連続生産量（単位） |
| `inventory` | `number[]` | 各期の非負期末製品在庫（単位） |
| `charge` | `number[]` | 各期の蓄電池充電電力（kW） |
| `discharge` | `number[]` | 各期の蓄電池放電電力（kW） |
| `soc` | `number[]` | 各期末の蓄電残量（SOC、kWh、最終期末は `initSoc` 以上） |
| `peakLoad` | `number` | 期間中の最大系統買電電力（kW） |
| `totalCost` | `number` | 最小化された生産＋電力総コスト |

<!-- section:example -->
**入力例**

```json
{
  "demands": [20, 35, 25, 30],
  "setupCost": 120,
  "holdCost": 1.5,
  "prodCap": 60,
  "setupPower": 10,
  "unitPower": 1.0,
  "baseLoads": [10, 85, 15, 90],
  "prices": [0.5, 2.0, 0.6, 2.2],
  "demandCharge": 8.0,
  "batteryCap": 80,
  "initSoc": 20,
  "maxPower": 35,
  "etaCharge": 0.8,
  "etaDischarge": 0.8
}
```

**出力例**

```json
{
  "setups": [1, 0, 1, 0],
  "production": [55, 0, 55, 0],
  "inventory": [35, 0, 30, 0],
  "charge": [8.597561, 0, 3.597561, 0],
  "discharge": [0, 1.402439, 0, 6.402439],
  "soc": [26.878049, 25.125, 28.003049, 20],
  "peakLoad": 83.597561,
  "totalCost": 1449.347561
}
```

安価な第 0・2 期にまとめて先行生産（`production = [55, 0, 55, 0]`）しつつ蓄電池を充電し、高料金の第 1・3 期に放電することで全期間の系統買電電力を 83.597561 に平準化し、段取り費 240 ＋ 保管費 97.5 ＋ 電力量料金 443.067073 ＋ デマンド料金 668.780488 で総コスト $240 + 97.5 + 443.067073 + 668.780488 \approx$ **1,449.35** となります。


<!-- section:hint1 -->
同じ計画期間上で、単一品目ロットサイズ計画の変数（バイナリの段取り、連続生産量、製品在庫）と蓄電池運用の変数（充電、放電、バイナリの充放電モード、蓄電残量（SOC）、系統買電電力、および最大系統買電電力のスカラー変数）を組み合わせて定義します。

<!-- section:hint2 -->
2 つのサブシステムは、補助変数として導入する非負の系統買電電力 `gridLoad[t]` を介した各期の電力バランス `gridLoad[t] = baseLoads[t] + setupPower * setups[t] + unitPower * production[t] + charge[t] - discharge[t] >= 0` で結合されます。さらに補助のバイナリモード変数 `mode[t]` で充放電の同時発生を禁止し、蓄電残量（SOC）の変化には `etaCharge` と `1 / etaDischarge` を適用し、最終期に `soc[T - 1] >= initSoc`、全期に `peakLoad >= gridLoad[t]` を課してください。
