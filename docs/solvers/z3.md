# Z3 SMT Solver Engine

**Z3** is an open-source theorem prover and Satisfiability Modulo Theories (SMT) solver from Microsoft Research. In WaSHI, Z3 handles logical rules involving `Continuous` or decimal variables, exact arithmetic, and `unsatCore` conflict diagnosis.

---

## Installation

`z3-solver` is an optional peer dependency:

```bash
npm install z3-solver
```

---

## When to Choose Z3

| Goal | Recommended Solver | Why |
| :--- | :--- | :--- |
| **Logical rules with `Continuous` or decimal values** | **Z3** (`m.check({ solver: "z3" })`) | Evaluates real-valued inequalities natively inside `implies`, `not`, `and`, `or`, and `xor`. |
| **Conflict diagnosis (`unsatCore`) with `Continuous` vars** | **Z3** (`m.check({ solver: "z3" })`) | Extracts scale-invariant `unsatCore` subsets across mixed continuous and integer models. |
| **Bounded integer/boolean Constraint Programming** | **[Pumpkin](./pumpkin.md)** | Bundled with zero dependencies and needs no Cross-Origin Isolation headers. |
| **Numerical linear, mixed-integer, or convex quadratic optimization** | **[HiGHS](./highs.md)** (default) | Built-in simplex, interior-point, and branch-and-cut solver; much faster for objective optimization. |

> [!TIP]
> A common workflow is to verify rules and diagnose conflicts via **Z3** `model.check()`, then optimize numerical costs via **HiGHS** `model.solve()`.

---

## Basic Usage (`model.solve()` vs. `model.check()`)

Import `@ohtaman/washi/solvers/z3` once to register the `"z3"` solver. Z3 supports two execution modes on the same `Model`:

- **`model.check()`**: Checks satisfiability without an objective and returns `"Sat"`, `"Unsat"` (with `conflicts` / `unsatCore`), or `"Unknown"`.
- **`model.solve()`**: Optimizes a linear objective via Z3 Optimize. When no objective is set, `solve()` finds any feasible assignment and reports `"Optimal"` (or `"Feasible"` if `signal` was aborted while the call was completing).

The example below finds a feasible assignment for a continuous threshold rule controlled by a boolean flag:

```typescript
import { Model, expr, implies } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });

const temp = model.continuous("temp", { lb: 0, ub: 100 });
const coolingOn = model.bool("cooling_on");

model.constraint(coolingOn, "enable_cooling");
model.constraint(implies(coolingOn, expr`${temp} <= 22.5`), "cooling_target");

// Without an objective, solve() finds any feasible assignment.
// Call model.check() instead for "Sat" / "Unsat" and unsatCore diagnostics.
await model.solve();
console.log(`Status: ${model.status}, temp = ${temp.value}`);
```

## Conflict Diagnosis (`model.check()`)

Call `await model.check()` to verify satisfiability across continuous, integer, or mixed rules. When the model is `"Unsat"`, Z3 returns a conflicting subset of named constraints via `result.conflicts` (also available as `result.unsatCore` and `model.unsatCore`):

```typescript
import { Model, expr } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });
const a = model.continuous("a");

model.constraint(expr`${a} >= 10`, "req_A");
model.constraint(expr`${a} <= 5`, "req_B");

const result = await model.check();

if (result.status === "Unsat") {
  console.log("Conflicting constraints:", result.conflicts);
  // ["req_A", "req_B"]
}
```

## Supported & Unsupported Options

Z3 validates options strictly and throws a runtime `Error` when unsupported options or model features are supplied.

### Supported Options

- `z3JsUrl` / `z3WasmUrl`: Override browser asset URLs for `z3-built.js` and `z3-built.wasm` (or configure globally with `setZ3Assets()`).
- `signal`: `AbortSignal` checked **before** Z3 starts solving (pre-solve cancellation only; it cannot interrupt an active Z3 call).
- `onProgress`: Invoked once after `solve()` completes with elapsed time and (when a solution exists) the final objective value.

### Unsupported Options & Features (Throw at Runtime)

- **Unsupported tuning options**: `timeLimit`, `relativeGap`, `absoluteGap`, `presolve`, `threads`, `verbose`, `outputFlag`, and unknown option keys throw an `Error`.
- **Unsupported modes & features**: `relax: true`, `useWorker: true`, `initialValue` warm starts, and `QuadExpr` quadratic objectives throw an `Error`.

> [!NOTE]
> Z3 Optimize is an SMT optimization engine and does not produce branch-and-bound dual bounds, so `objectiveBound`, `relativeGap`, and `absoluteGap` remain `undefined` on Z3 results.

## Browser Requirements & Thread Cleanup

In browsers, Z3 uses `SharedArrayBuffer` and Emscripten pthreads. Your page must satisfy two browser preconditions:

1. **Secure Context**: Served over `HTTPS` or `localhost`.
2. **Cross-Origin Isolation (`COOP`/`COEP`)**: Document responses must send `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`.

See the [Cross-Origin Isolation Guide](../getting-started/cross-origin.md) for server setup. If you cannot configure these headers and only need bounded integers and booleans, use [Pumpkin](./pumpkin.md) instead.

If a Z3 worker hits a fatal error, the pending promise rejects and the broken runtime is discarded so the next call starts cleanly. To shut down Z3 pthread workers explicitly (for example, when unmounting a view), call:

```typescript
import { killZ3Threads } from "@ohtaman/washi/solvers/z3";

await killZ3Threads();
```
