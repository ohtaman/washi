# #014. 論理条件と Big-M による設備稼働最適化

<!-- section:scenario -->
インフラ運用チームが、総稼働予算のもとで候補設備の稼働有無と各設備の連続稼働水準を決定します。稼働させた設備には固定費がかかり、連続稼働水準はその設備の最小値から最大値までの範囲内にする必要があります（停止時はゼロです）。

さらに運用ルールとして、ある設備の稼働が別設備の稼働を前提とする条件、2つの設備を同時に稼働させると補助設備の稼働も必須となる連動条件、そして同時に稼働できない排反ペアが定められています。全ルールと予算を守りながら、**純利益（リターン合計 − 固定費合計）を最大化**してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `budget` | `number` | 全設備の稼働水準合計に対する予算上限 |
| `unitReturns` | `number[]` | 各設備の稼働水準 1 単位あたりのリターン |
| `fixedCosts` | `number[]` | 各設備を稼働させたときの固定費 |
| `minLevels` | `number[]` | 稼働時の最小連続水準 |
| `maxLevels` | `number[]` | 稼働時の最大連続水準 |
| `prerequisites` | `number[][]` | ペア `[a, b]`（`a` が稼働なら `b` も稼働必須） |
| `conjunctions` | `number[][]` | 組 `[a, b, c]`（`a` と `b` の両方が稼働なら `c` も稼働必須） |
| `conflicts` | `number[][]` | ペア `[u, v]`（両方は同時に稼働不可） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `active` | `number[]` | 各設備の稼働選択（`0` または `1`） |
| `levels` | `number[]` | 各設備の連続稼働水準 |
| `netProfit` | `number` | 最大化された純利益 |

<!-- section:example -->
**入力例**

```json
{
  "budget": 55,
  "unitReturns": [6, 22, 24, 10, 20],
  "fixedCosts": [90, 80, 75, 110, 95],
  "minLevels": [10, 15, 14, 12, 16],
  "maxLevels": [18, 22, 20, 14, 24],
  "prerequisites": [[1, 0]],
  "conjunctions": [[1, 2, 3]],
  "conflicts": [[2, 4]]
}
```

**出力例**

```json
{
  "active": [1, 1, 0, 0, 1],
  "levels": [10, 22, 0, 0, 23],
  "netProfit": 739
}
```

設備 `{0, 1, 4}` を稼働させて `levels = [10, 22, 0, 0, 23]` とすると、前提条件 `1 -> 0`・排反 `[2, 4]`・連動条件および予算 $10 + 22 + 23 = 55 \le 55$ をすべて満たし、純利益は $(60 + 484 + 460) - (90 + 80 + 95) =$ **739** となります。

<!-- section:hint1 -->
各設備には稼働を表すバイナリ変数と連続量の稼働水準変数があります。各ペアの稼働範囲を連結し、全設備の水準合計を予算で抑えたうえで、3 種類の論理規則（前提・連動・排反）をバイナリ変数上の線形不等式として表現します。

<!-- section:hint2 -->
`levels[i]` と `active[i]` の連結には各設備固有のタイトな境界（`minLevels[i]` と `maxLevels[i]`）を使います。論理制約は、含意 $a \implies b$ を $y_a \le y_b$、排反を $y_u + y_v \le 1$、連言 $(a \land b) \implies c$ を $y_a + y_b - 1 \le y_c$（$a$ と $b$ が両方 $1$ のときだけ発動）として線形化できます。
