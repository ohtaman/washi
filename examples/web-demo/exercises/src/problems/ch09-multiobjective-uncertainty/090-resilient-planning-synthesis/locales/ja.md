# #090. レジリエント計画・復旧統合演習（第9章総合）

<!-- section:scenario -->
電力網の計画担当者は、事前に稼働させる発電ユニットの 0-1 事前契約を決定し、各ユニットの固定確保費を支払います。通常時は各ユニットが公称容量を発揮しますが、第 1 段階のロバスト評価では、各契約ユニットが最大容量低下量の区間 $[0, 1]$ の任意の割合だけ低下しうるとし（全ユニットの割合の合計は与えられた不確実性予算 `gamma` 以下、小数可）、その範囲内の最悪低下時でも残存容量が要求されるロバスト基準値を下回ってはなりません。

その後、既知の確率に従って障害シナリオのいずれかが発生し、各シナリオ固有の需要量と運転不能ユニット（強制停止）が確定します。停止ユニットを避けつつ各シナリオの復旧 0-1 スケジュールを決定し（第 2 段階で稼働するユニットは公称容量を供給します）、事前契約から稼働・停止を切り替えたユニット 1 基ごとの変更コストと未充足需要 1 単位あたりの不足ペナルティを含めた**固定費と期待復旧・不足コストの和を最小化**してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `fixedCosts` | `number[]` | 第 1 段階における各ユニットの固定確保費 |
| `capacities` | `number[]` | 各ユニットの公称供給容量 |
| `dropAmounts` | `number[]` | 第 1 段階のロバスト評価で想定する各ユニットの最大容量低下量 |
| `gamma` | `number` | 第 1 段階の容量低下に対する不確実性予算（0 以上・ユニット数以下、小数可） |
| `robustMinCap` | `number` | 最悪の予算内低下時にも確保すべき第 1 段階の最小残存容量 |
| `probs` | `number[]` | 各シナリオの生起確率（合計 1） |
| `demands` | `number[]` | 各シナリオで発生する需要量 |
| `offline` | `number[][]` | シナリオ別・ユニット別の運転不能マスク行列（[scenario][unit]、1 で強制停止） |
| `disruptionCost` | `number` | 事前契約から状態を切り替えるユニット 1 基あたりの変更コスト |
| `shortfallPenalty` | `number` | いずれのシナリオでも適用される未充足需要 1 単位あたりの不足ペナルティ |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `committed` | `number[]` | 第 1 段階の事前契約 0-1 ベクトル |
| `recovered` | `number[][]` | シナリオ別・ユニット別の復旧 0-1 スケジュール行列（[scenario][unit]） |
| `totalCost` | `number` | 最小化された固定費＋期待復旧・不足コスト |

<!-- section:example -->
**入力例**

```json
{
  "fixedCosts": [120, 150, 90, 110],
  "capacities": [18, 22, 12, 16],
  "dropAmounts": [8, 10, 4, 6],
  "gamma": 1,
  "robustMinCap": 28,
  "probs": [0.6, 0.4],
  "demands": [24, 34],
  "offline": [
    [0, 0, 0, 0],
    [0, 1, 0, 0]
  ],
  "disruptionCost": 45,
  "shortfallPenalty": 30
}
```

**出力例**

```json
{
  "committed": [0, 1, 0, 1],
  "recovered": [
    [0, 1, 0, 1],
    [1, 0, 0, 1]
  ],
  "totalCost": 296
}
```

事前契約 `[0, 1, 0, 1]` は固定費 $150 + 110 = 260$ で最悪 1 基低下時の残存容量 $22 + 16 - 10 = 28 \ge 28$ を満たし、シナリオ 0 は変更なし、シナリオ 1 はユニット 1 から 0 へ切替（変更 2 基・容量 $34 \ge 34$）となるため期待総費用は $260 + 0.6(0) + 0.4(45 \times 2) =$ **296** となります。


<!-- section:hint1 -->
第 1 段階のバイナリコミットメント変数と Bertsimas-Sim 双対保護変数に、シナリオ別の第 2 段階バイナリ復旧スケジュール変数・連続切替変数・非負需要不足量変数を組み合わせます。第 1 段階では最悪ケースの残存容量が `robustMinCap` 以上であることを保証し、第 2 段階では各シナリオの停止制約を守りつつ期待切替コストと不足ペナルティの和を最小化します。

<!-- section:hint2 -->
3 つの落とし穴に注意してください。(1) 第 1 段階の残存容量は下限ロバスト制約なので、Bertsimas-Sim 双対で表される最悪容量低下量は加算ではなく公称容量から**差し引き**ます。(2) 切替指標 $|w_{s,j} - y_j|$ は、区間 $[0, 1]$ の連続変数と正負 2 本の差の不等式で線形化できます。(3) 各シナリオで `offline` が 1 のユニットは稼働変数を 0 に固定し、バイナリ出力 `committed` と `recovered` はきれいな 0/1 の整数に丸めて返してください。
