# #058. 取送货车辆路径问题 (PDP)

<!-- section:scenario -->
最多 `maxVehicles` 辆相同车辆从配送中心 0 出发，服务多笔由取货点、送货点和货物重量组成的成对取送货订单：

- 每条启用路径均从配送中心 0 出发并返回 0，总派车数不超过 `maxVehicles`。
- 所有订单的取货点与送货点互不相同，构成站点 `1..N-1`，且每个站点必须恰好被访问一次。
- 同一订单的取货与送货必须由同一辆车完成，且先取后送。
- 沿途任一时刻车上累计载重不得超过单车容量 `capacity`，每辆车停靠的非配送中心站点数也不得超过 `maxStopsPerVehicle`。

请规划满足上述条件的车辆路径，**最小化总行驶距离**。

<!-- section:io -->
### 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `dist` | `number[][]` | $N \times N$ 距离矩阵（0 为配送中心，`1..N-1` 为取送货站点） |
| `requests` | `Array<{ pickup: number; delivery: number; demand: number }>` | 订单列表（取货点 `pickup`、送货点 `delivery`、货量 `demand`；各站点编号恰好划分 `1..N-1`） |
| `capacity` | `number` | 单车最大载重容量 $Q$ |
| `maxVehicles` | `number` | 最多可派出的车辆数 |
| `maxStopsPerVehicle` | `number` | 单辆车最多可访问的非配送中心站点数量 |

### 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `routes` | `number[][]` | 车辆路径列表，每条均形如 `[0, ..., 0]` |
| `totalDistance` | `number` | 最小化后的全部路径总里程 |

<!-- section:example -->
**输入示例**

```json
{
  "dist": [
    [0, 2, 7, 4, 8],
    [2, 0, 5, 1, 6],
    [7, 5, 0, 4, 1],
    [4, 1, 4, 0, 5],
    [8, 6, 1, 5, 0]
  ],
  "requests": [
    { "pickup": 1, "delivery": 2, "demand": 3 },
    { "pickup": 3, "delivery": 4, "demand": 4 }
  ],
  "capacity": 7,
  "maxVehicles": 1,
  "maxStopsPerVehicle": 4
}
```

**输出示例**

```json
{
  "routes": [
    [0, 1, 3, 2, 4, 0]
  ],
  "totalDistance": 16
}
```

路线 `[0, 1, 3, 2, 4, 0]` 先于站点 1（载重 3）和站点 3（载重 7 ≤ 7）完成两次取货，再依次前往站点 2 与 4 卸货，满足配对、先后序与停靠限制，总距离为 $2 + 1 + 4 + 1 + 8 =$ **16**。

<!-- section:hint1 -->
为二进制弧选择变量增加车辆下标 `k`，以便直接约束同一请求的取货点与送货点由同一辆车服务。同时为每个地点定义连续访问顺序变量和累计载重变量，约束每个非配送中心站点恰好访问一次、每辆车流量守恒，且单车停靠点数不超过 `maxStopsPerVehicle`。

<!-- section:hint2 -->
由于取货增加载重而送货减少载重，无法像普通 CVRP 那样仅靠单调递增的载重 MTZ 消除子环路。请将用于消环和先后序（$t_p + 1 \le t_d$）的访问顺序变量 $t_i$（$t_0 = 0$）与载重变量 $L_i \in [0, Q]$（$L_0 = 0$）分开建模，并在激活弧上用 Big-M 约束 $L$ 在取货点增加 $+q_r$、在送货点减少 $-q_r$。
