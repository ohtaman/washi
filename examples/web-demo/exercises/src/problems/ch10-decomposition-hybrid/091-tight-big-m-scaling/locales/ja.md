# #091. タイトな Big-M とスケーリング改善

<!-- section:scenario -->
製造業において、どの工場を稼働させるかと各工場での生産量を決定し、固定費と変動生産費の合計を最小化しながら総需要を満たします。物理的な最大生産能力が総需要を大きく上回る工場が含まれる場合、巨大な定数や生の工場能力をそのまま Big-M に使うと連続 LP 緩和の下界が大きく弱まります。

各工場についてインスタンスから導出できる最もタイトな Big-M を用いて稼働・生産量の連結制約を定式化し、整数最適解とあわせてそのタイト定式化の LP 緩和目的値も返してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `fixedCosts` | `number[]` | 工場 $i$ の稼働時に発生する固定費 |
| `unitCosts` | `number[]` | 工場 $i$ での 1 単位あたり生産コスト |
| `capacities` | `number[]` | 工場 $i$ の物理的な最大生産能力 |
| `demand` | `number` | 満たすべき総需要量 |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `open` | `number[]` | 各工場の稼働選択（`0` または `1`） |
| `quantities` | `number[]` | 各工場の非負連続生産量 |
| `totalCost` | `number` | 最小化された総コスト（固定費＋変動費） |
| `lpBound` | `number` | タイト Big-M 定式化の連続 LP 緩和目的値 |

<!-- section:example -->
**入力例**

```json
{
  "fixedCosts": [1000, 200, 450],
  "unitCosts": [10, 12, 11],
  "capacities": [500, 40, 80],
  "demand": 60
}
```

**出力例**

```json
{
  "open": [0, 0, 1],
  "quantities": [0, 0, 60],
  "totalCost": 1110,
  "lpBound": 1050
}
```

工場 2 のみを稼働させて $60 \le 80$ 単位を生産すると総需要 $60$ を満たし、総コストは $450 + 11 \times 60 =$ **1,110**、タイト Big-M による LP 緩和下界は **1,050** となります。

<!-- section:hint1 -->
各工場について稼働の有無を表す二値変数と非負の連続生産量変数を用意します。総需要を満たす制約と各工場の生産量を稼働変数に紐づける制約のもとで、固定費と変動生産費の合計を最小化します。

<!-- section:hint2 -->
どの工場も総需要を超えて生産する必要はないため、工場 $i$ の最もタイトな Big-M は生の工場能力や任意の大きな定数ではなく $M_i = \min(\text{capacities}[i], \text{demand})$ になります。WaSHI では MIP を 1 つ構築して `await m.solve()` の前に `await m.relax()` で `lpBound` を取得し、PuLP では連続緩和（二値変数を $[0, 1]$ に緩和）と MIP の両方を解きます。
