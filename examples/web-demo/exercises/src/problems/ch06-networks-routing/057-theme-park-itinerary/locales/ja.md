# #057. テーマパーク・グループ周遊計画（時間枠付き）

<!-- section:scenario -->
最大 `maxGroups` 組のグループが開園時刻にテーマパークの入口（地点 0）から出発し、指定されたすべてのアトラクションをちょうど 1 回ずつ体験したうえで、閉園時刻までに入口へ戻る必要があります。各アトラクションには受付開始から終了までの許容開始時刻枠と体験所要時間が決まっており、早く着いた場合は受付開始時刻まで待機できますが、受付終了時刻を過ぎてからの開始は許されません。

最大 `maxGroups` 組の周遊ルートを計画してすべての時間枠と閉園時刻を満たし、**総徒歩移動時間を最小化**してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `travelTimes` | `number[][]` | $(n+1) \times (n+1)$ の徒歩移動時間行列（0 は入口、1..n はアトラクション） |
| `earliest` | `number[]` | 各地点での最も早い開始許容時刻（`earliest[0] = 0`） |
| `latest` | `number[]` | 各アトラクションの最も遅い開始許容時刻。`latest[0]` は閉園帰着期限 |
| `visitDurations` | `number[]` | 各地点での体験所要時間（`visitDurations[0] = 0`） |
| `maxGroups` | `number` | 入口 0 を出発できるグループ数の上限 |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `itineraries` | `number[][]` | 各グループの周遊順リスト（各行程は `[0, ..., 0]`） |
| `totalCost` | `number` | 全グループの徒歩移動時間の合計最小値 |

<!-- section:example -->
**入力**

```json
{
  "travelTimes": [
    [0, 4, 7, 5, 3],
    [4, 0, 5, 4, 6],
    [7, 5, 0, 4, 7],
    [5, 4, 4, 0, 5],
    [3, 6, 7, 5, 0]
  ],
  "earliest": [0, 12, 5, 2, 14],
  "latest": [45, 18, 14, 9, 24],
  "visitDurations": [0, 3, 2, 3, 2],
  "maxGroups": 2
}
```

**出力**

```json
{
  "itineraries": [
    [0, 1, 0],
    [0, 3, 2, 4, 0]
  ],
  "totalCost": 27
}
```

`[0, 1, 0]` はアトラクション1で `t = 12` まで待機して `19 <= 45` に帰着（移動時間 8）、`[0, 3, 2, 4, 0]` は `t = [5, 12, 21]` に開始して `26 <= 45` に帰着（移動時間 19）するため、総移動時間は $8 + 19 =$ **27** となります。

<!-- section:hint1 -->
異なる2地点間のバイナリ移動変数、`[earliest[i], latest[i]]` を上下限とする連続の体験開始時刻変数、およびアトラクションの訪問順ポテンシャル変数を用意します。入口の出発時刻を固定し、各アトラクションの次数を1に制約し、入口の出次数・入次数を `maxGroups` 以下で一致させてください。

<!-- section:hint2 -->
採用された移動 `(i, j)` に沿って開始時刻をタイトな Big-M 不等式（$t_i + s_i + d_{ij} - t_j \le M_{ij}(1 - x_{ij})$、ただし $M_{ij} = \max(0, l_i + s_i + d_{ij} - e_j)$）で連結し、帰着辺 `(i, 0)` にも閉園時刻制約を課します。移動時間と体験時間の和が 0 の隣接アトラクション（`visitDurations + travelTimes == 0`）があると時刻単調性だけでは入口を通らない小ループを防げないため、アトラクション間の MTZ 順序制約も併用してください。
