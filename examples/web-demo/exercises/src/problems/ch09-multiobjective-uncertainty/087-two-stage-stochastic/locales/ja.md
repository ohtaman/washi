# #087. リコース付き2段階確率計画法

<!-- section:scenario -->
食品・日用品の卸売事業者は、不確実な顧客需要が判明する前の第 1 段階で、共有倉庫の上限容量（単位：ケース）の範囲内で複数商品の発注量（ケース）を決定します。ここで発注した分には商品ごとの初期仕入単価（円／ケース）がかかります。

その後、既知の確率に従っていずれかの需要シナリオが実現すると、第 2 段階の補正対応（リコース行動）が行われます。需要に対して在庫が不足した分には高額な緊急補充ペナルティ（円／ケース）がかかり、売れ残った在庫からはより小さな残存回収価値（サルベージ収入、円／ケース）が得られます。初期発注費と第 2 段階の期待純コストの和を最小化する第 1 段階発注量を求めてください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `orderCosts` | `number[]` | 各商品の第 1 段階仕入単価（円／ケース） |
| `shortageCosts` | `number[]` | 各商品の第 2 段階欠品 1 ケースあたりのペナルティ（円） |
| `salvageValues` | `number[]` | 各商品の売れ残り 1 ケースあたりの回収価値（円） |
| `warehouseCap` | `number` | 第 1 段階の総発注量に対する共有倉庫容量上限（ケース） |
| `probs` | `number[]` | 各シナリオ $s$ の生起確率 $p_s$ |
| `demands` | `number[][]` | シナリオ別需要行列（$S \times n$、ケース） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `orders` | `number[]` | 第 1 段階の発注量ベクトル（非負値、ケース） |
| `expectedCost` | `number` | 全シナリオにわたる最小化された期待総費用（円） |

<!-- section:example -->
**入力例**

```json
{
  "orderCosts": [4, 6],
  "shortageCosts": [14, 18],
  "salvageValues": [1, 2],
  "warehouseCap": 30,
  "probs": [0.5, 0.5],
  "demands": [
    [10, 8],
    [20, 16]
  ]
}
```

**出力例**

```json
{
  "orders": [14, 16],
  "expectedCost": 184
}
```

`orders = [14, 16]` は倉庫上限 $14 + 16 = 30 \le 30$ を満たし、初期費用 $4(14) + 6(16) = 152$、シナリオ 0 の残存回収 $20$、シナリオ 1 の欠品費 $84$ から期待総費用は $152 + 0.5(-20) + 0.5(84) =$ **184** となります。


<!-- section:hint1 -->
全シナリオで共有される第 1 段階の発注量（非負変数）と、シナリオ別の第 2 段階の不足量・余剰在庫（いずれも非負変数）を定義し、全シナリオを 1 本の大きな線形計画問題に展開した確定等価 LP を定式化します。第 1 段階の総発注量を倉庫容量で制約し、各シナリオのリコース変数を需要に結び付け、初期発注コストと確率重み付き期待リコースコストの和を最小化します。

<!-- section:hint2 -->
第 1 段階の発注量はシナリオに依存しない単一ベクトルとして共有する（非先見性）点と、最小化目的関数における残存価値の符号に注意してください。残存価値は回収収入なので負符号で差し引く必要があります。`shortageCosts` が `salvageValues` より大きいため、最適解で同一商品・シナリオに不足と余剰が同時に立つことはありません。
