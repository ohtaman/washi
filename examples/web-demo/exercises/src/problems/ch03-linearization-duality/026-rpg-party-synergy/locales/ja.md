# #026. RPG パーティのシナジー最大化

<!-- section:scenario -->
冒険者は候補となるヒーローの一覧からダンジョン攻略パーティを編成しようとしています。各ヒーローには基本戦力と雇用コスト（ゴールド）が設定されており、次の条件を満たす必要があります。

- **予算上限**: 採用したヒーローの雇用コスト合計が利用可能な予算（ゴールド）以内であること。
- **人数上限**: 採用するヒーローの人数が編成枠上限以内であること。
- **ペア相互作用**: 指定されたヒーロー同士を同時に採用すると、シナジーボーナス（正の値）または対立ペナルティ（負の値）が発生すること。

これらを満たすヒーローの採用有無と各ペアの同時採用フラグを決定し、**基本戦力とペア効果の合計を最大化**してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `power` | `number[]` | 各ヒーローの基本戦力 |
| `costs` | `number[]` | 各ヒーローの雇用コスト（ゴールド） |
| `budget` | `number` | 利用可能な総予算上限（ゴールド） |
| `maxPartySize` | `number` | パーティ人数の上限 |
| `pairs` | `number[][]` | 相互作用リスト `[i, j, s]`（`i`, `j` は 0 始まりのヒーロー添字、$s > 0$ はシナジーボーナス、$s < 0$ は対立ペナルティ） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `selected` | `number[]` | ヒーローごとの 0-1 採用フラグ $x_i$ |
| `pairProducts` | `number[]` | 各ペアの同時採用フラグ $w_k = x_i x_j$ |
| `totalValue` | `number` | 最大化されたパーティ総戦力 |

<!-- section:example -->
**入力例**

```json
{
  "power": [40, 35, 30, 25],
  "costs": [25, 25, 20, 15],
  "budget": 60,
  "maxPartySize": 2,
  "pairs": [
    [0, 1, 25],
    [1, 2, -20],
    [0, 3, 10],
    [2, 3, 15]
  ]
}
```

**出力例**

```json
{
  "selected": [1, 1, 0, 0],
  "pairProducts": [1, 0, 0, 0],
  "totalValue": 100
}
```

ヒーロー 0 と 1 を採用（[1, 1, 0, 0]）すると、人数は $2 \le 2$ 人、コストは $25 + 25 = 50 \le 60$ ゴールド、同時採用ペアは (0, 1) のみ（`pairProducts` は [1, 0, 0, 0]）となり、総戦力は $40 + 35 + 25 =$ **100** になります。

<!-- section:hint1 -->
各ヒーロー候補について採用有無を表すバイナリ決定変数を 1 つ、相互作用ペアごとに 0 以上 1 以下の連続補助変数を 1 つ宣言します。ヒーローの採用有無が 0 または 1 に限られるため、両者を結ぶ線形制約を課せばペア変数は連続変数のままでも厳密に 0 または 1 に定まります。

<!-- section:hint2 -->
予算上限と人数上限の制約に加えて、各ペアの積 $w_k = x_i x_j$ を 3 本の不等式からなる McCormick（Fortet）包絡で線形化します。各ヒーローの採用変数で抑える 2 本の上界は、片方でも欠けた状態で正のシナジーボーナス（$s > 0$）を不当に得るのを防ぎ、両方採用時に $w_k = 1$ を強制する 1 本の下界は、負の対立ペナルティ（$s < 0$）の回避を防ぎます。相互作用の符号が正負混在するため上下両方が不可欠です。整数出力として返す際は `pairProducts` を丸めてください。
