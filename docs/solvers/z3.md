# Z3 SMT Solver Engine

**Z3** is a theorem prover and SMT solver from Microsoft Research. In WaSHI, Z3 is best used for logical rules involving `Continuous` or decimal variables, exact arithmetic, and `unsatCore` conflict diagnosis.

---

## Installation

Z3 is an optional peer dependency:

```bash
npm install z3-solver
```

---

## When to Use Z3 vs. HiGHS or Pumpkin

| Goal | Recommended Solver | Why |
| :--- | :--- | :--- |
| **Logical rules with `Continuous` / decimal values** | **Z3** (`m.check({ solver: "z3" })`) | Handles real-valued inequalities inside `implies`, `not`, `and`, `or`. |
| **Conflict diagnosis (`unsatCore`) with `Continuous` vars** | **Z3** (`m.check({ solver: "z3" })`) | Extracts scale-invariant `unsatCore` across mixed continuous/integer models. |
| **Bounded integer / boolean CP & `unsatCore` without `COOP`/`COEP`** | **Pumpkin** (`@ohtaman/washi/solvers/pumpkin`) | Bundled with zero dependencies and no `SharedArrayBuffer` headers needed. |
| **Numerical LP / MIP / QP optimization** | **HiGHS** (`m.solve()`) | Orders of magnitude faster for objective optimization. |

> [!TIP]
> A common pattern is to verify or diagnose rules with `Z3` (`m.check()`) and optimize costs with `HiGHS` (`m.solve()`).

## Basic Usage

```typescript
import { Model, expr } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });

const x = model.integer("x", { lb: 0, ub: 10 });
const y = model.integer("y", { lb: 0, ub: 10 });

model.constraint(expr`${x} + ${y} == 15`, "sum_15");
model.constraint(expr`${x} >= 8`, "x_at_least_8");

await model.solve();
console.log(`Status: ${model.status}, x = ${x.value}, y = ${y.value}`);
```

## Conflict Diagnosis (`model.check()`)

Call `await model.check()` to check satisfiability and extract conflicting named constraints (`conflicts` / `unsatCore`) when the model is unsatisfiable:

```typescript
import { Model, expr } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });
const a = model.continuous("a");

model.constraint(expr`${a} >= 10`, "req_A");
model.constraint(expr`${a} <= 5`, "req_B");

const result = await model.check();

if (result.status === "Unsat") {
  console.log("Conflicting constraints:", result.conflicts); // or model.conflicts / model.unsatCore
  // ["req_A", "req_B"]
}
```

## Browser Requirements & Thread Cleanup

In browsers, Z3 uses `SharedArrayBuffer` and pthreads, so your server must send `COOP` / `COEP` headers (see [Cross-Origin Isolation Guide](../getting-started/cross-origin.md)). If you cannot set those headers and only use bounded integers and booleans, use [Pumpkin](./pumpkin.md) instead.

If a Z3 worker hits a fatal runtime error, the pending promise rejects and the broken runtime is discarded so the next `solve()` or `check()` starts a clean instance. To shut down Z3 pthread workers explicitly (for example, when unmounting a view), call:

```typescript
import { killZ3Threads } from "@ohtaman/washi/solvers/z3";

await killZ3Threads();
```
