# #026. 0-1 変数同士の積の線形化（相乗効果・競合選択）

<!-- section:scenario -->
開発チームは、限られた予算内で実装する機能モジュールの部分集合を選定しています。各モジュールには単体価値と開発コストが設定されており、さらに特定のペアを両方同時に実装すると相乗効果（正のボーナス）または機能競合（負のペナルティ）が発生します。

予算上限を守りながら、各モジュールの採否と各ペアの同時採用フラグを決定し、**単体価値とペア効果の合計を最大化**してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `values` | `number[]` | モジュール $i$ の単体価値 $r_i$ |
| `costs` | `number[]` | モジュール $i$ のコスト $c_i$ |
| `budget` | `number` | 総予算上限 $B$ |
| `pairs` | `number[][]` | `[i, j, s]` のリスト（$s > 0$ は相乗効果、$s < 0$ は競合ペナルティ） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `selected` | `number[]` | モジュールごとの 0-1 採否 $x_i$ |
| `pairProducts` | `number[]` | 各ペアの同時採用フラグ $w_k = x_i x_j$ |
| `totalValue` | `number` | 最大化された総価値 |

<!-- section:example -->
**入力例**

```json
{
  "values": [40, 35, 30, 25],
  "costs": [30, 25, 20, 15],
  "budget": 60,
  "pairs": [
    [0, 1, 25],
    [1, 2, -20],
    [0, 3, 10],
    [2, 3, 15]
  ]
}
```

**出力例**

```json
{
  "selected": [1, 1, 0, 0],
  "pairProducts": [1, 0, 0, 0],
  "totalValue": 100
}
```

モジュール 0 と 1 を採用（`[1, 1, 0, 0]`）するとコストは $30 + 25 = 55 \le 60$、同時採用ペアは `(0, 1)` のみ（`pairProducts = [1, 0, 0, 0]`）となり、総価値は $40 + 35 + 25 =$ **100** になります。


<!-- section:hint1 -->
各モジュール候補に対してバイナリ決定変数を 1 つ、相互作用ペアごとに $[0, 1]$ の連続補助変数を 1 つ宣言します。モジュール選択がバイナリであるため、McCormick 不等式によりペア変数は追加のバイナリ指定なしでも厳密に `0` または `1` に定まります。

<!-- section:hint2 -->
$w_k = x_i x_j$ に対する厳密な McCormick 包絡制約を課します。2 本の上界制約（$w_k \le x_i$ と $w_k \le x_j$）は両モジュールが選ばれない限り $w_k$ を 0 に抑え、下界制約（$w_k \ge x_i + x_j - 1$）は両方が選ばれたときに $w_k = 1$ を強制します。相互作用の重み $s$ は正（シナジー：上界がないと $w_k$ が過大評価される）にも負（競合：下界がないと $w_k$ が 0 に逃げられる）にもなり得るため、上下両方の制約が不可欠です。整数出力として返す際は `pairProducts` を丸めてください。
