# Z3 SMT ソルバーエンジン

**Z3** は Microsoft Research が開発したオープンソースの定理証明器・充足可能性モジュロ理論（SMT）ソルバーです。WaSHI では主に、`Continuous` 変数や小数を含む論理ルール、厳密な算術判定、`unsatCore` による矛盾診断に使います。

---

## インストール

Z3 はオプションの peer dependency です。

```bash
npm install z3-solver
```

---

## Z3 を選ぶ基準

| 目的 | 推奨ソルバー | 選定理由 |
| :--- | :--- | :--- |
| **`Continuous` 変数・小数を含む論理ルール** | **Z3**（`m.check({ solver: "z3" })`） | `implies`・`not`・`and`・`or` の中で実数の不等式をネイティブ評価。 |
| **`Continuous` 変数を含むモデルの矛盾診断** | **Z3**（`m.check({ solver: "z3" })`） | 数値の桁数に影響されず、連続・整数混在モデルから `unsatCore` を抽出。 |
| **有界整数・真偽値の制約プログラミング** | **[Pumpkin](./pumpkin.md)** | 標準同梱・追加依存なしで、Cross-Origin Isolation ヘッダーも不要。 |
| **線形・混合整数・二次の数値最適化** | **[HiGHS](./highs.md)**（デフォルト） | 標準搭載のシンプレックス・分枝カット法で、目的関数の最適化が高速。 |

> [!TIP]
> ルール検証や矛盾診断は **Z3** の `model.check()`、コストの数値最適化は **HiGHS** の `model.solve()` で使い分ける構成が実用的です。

---

## 基本的な使い方 (`model.solve()` と `model.check()`)

`@ohtaman/washi/solvers/z3` を一度インポートすると `"z3"` ソルバーが登録されます。同じ `Model` 上で次の 2 つの実行モードを使い分けられます。

- **`model.check()`**: 目的関数なしで充足可能性を判定し、`"Sat"`・`"Unsat"`（`conflicts` / `unsatCore` 付き）・`"Unknown"` を返します。
- **`model.solve()`**: 線形目的関数を最適化します。目的関数がない場合は任意の実行可能解を探し、充足可能なら `"Optimal"`（中断時は `"Feasible"`）を返します。

次の例は、真偽値フラグで制御される連続変数のしきい値ルールを判定します。

```typescript
import { Model, expr, implies } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });

const temp = model.continuous("temp", { lb: 0, ub: 100 });
const coolingOn = model.bool("cooling_on");

model.constraint(coolingOn, "enable_cooling");
model.constraint(implies(coolingOn, expr`${temp} <= 22.5`), "cooling_target");

// 目的関数なしの solve() は任意の実行可能解を返します。
// "Sat" / "Unsat" や unsatCore が欲しい場合は model.check() を使ってください。
await model.solve();
console.log(`Status: ${model.status}, temp = ${temp.value}`);
```

## 矛盾診断 (`model.check()`)

`await model.check()` を呼ぶと、連続変数と整数変数が混在するルールの充足可能性を判定します。結果が `"Unsat"` の場合、矛盾する名前付き制約を `result.conflicts`（`model.unsatCore` も同値）で返します。

```typescript
import { Model, expr } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });
const a = model.continuous("a");

model.constraint(expr`${a} >= 10`, "req_A");
model.constraint(expr`${a} <= 5`, "req_B");

const result = await model.check();

if (result.status === "Unsat") {
  console.log("矛盾している制約:", result.conflicts);
  // ["req_A", "req_B"]
}
```

## 対応・未対応オプションと制限事項

Z3 はオプションを厳密に検証し、未対応のオプションや機能を受け取ると実行時に `Error` を投げます。

### 対応オプション

- `z3JsUrl` / `z3WasmUrl`: ブラウザ上の `z3-built.js` と `z3-built.wasm` の読み込み URL を上書きします（グローバル設定は `setZ3Assets()`）。
- `signal`: Z3 の実行開始**前**にのみ中断状態を確認します（実行中の求解は途中中断できません）。
- `onProgress`: 求解完了時に 1 回だけ呼ばれ、経過時間と最終目的関数値を通知します。

### 未対応オプションと機能（実行時にエラー）

- **未対応の制御オプション**: `timeLimit`・`relativeGap`・`absoluteGap`・`presolve`・`threads`・`verbose`・`outputFlag` は `Error` を投げます。
- **未対応のモード・機能**: `relax: true`・`useWorker: true`・`initialValue`・`QuadExpr` と未定義キーも `Error` を投げます。

> [!NOTE]
> Z3 Optimize は分枝限定法の双対境界を公開しないため、`objectiveBound`・`relativeGap`・`absoluteGap` は `undefined` のままになります。

## ブラウザ要件とスレッドの終了

ブラウザでは Z3 が `SharedArrayBuffer` と Emscripten の pthread を使うため、次の 2 つの前提条件を満たす必要があります。

1. **Secure Context**: ページが `HTTPS` または `localhost` で配信されていること。
2. **Cross-Origin Isolation（`COOP`/`COEP`）**: 応答ヘッダーに `Cross-Origin-Opener-Policy: same-origin` と `Cross-Origin-Embedder-Policy: require-corp` を付与すること。

サーバーの設定例は [Cross-Origin Isolation 設定](../getting-started/cross-origin.md) を参照してください。ヘッダーを設定できず有界整数と真偽値のみを扱う場合は [Pumpkin](./pumpkin.md) を利用してください。

Z3 ワーカーで致命的なエラーが起きると実行中の Promise が reject され、壊れたランタイムが破棄されるため次回の呼び出しは新しいインスタンスで再開されます。コンポーネント破棄時などにワーカーを明示終了するには次を呼び出します。

```typescript
import { killZ3Threads } from "@ohtaman/washi/solvers/z3";

await killZ3Threads();
```
