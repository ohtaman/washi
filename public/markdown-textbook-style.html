Chapter 01 Tag in the Labyrinth — From Dijkstra to A* Search

Picture an action RPG or roguelike dungeon crawler where monsters seamlessly navigate around trees, walls, and traps to pursue the player. Behind this behavior lies the fundamental technique of Shortest Pathfinding.

KEY QUESTION
If examining every grid tile sequentially guarantees finding the shortest route, why do we need A* search?
Exhaustive breadth-first search blindly expands outward in all directions—even directly away from the target. On large game maps, this causes state-space explosion. A* solves this by adding a "heuristic estimate" toward the destination, focusing exploration strictly toward the goal.
📊 Search Space Expansion Comparison
Breadth-First Search (Omnidirectional)
. . ◯ . . . ◯ ◯ ◯ . ◯ ◯ [S] ◯ ◯ . ◯ ◯ ◯ . [G] . . ◯ . . * Expands radially regardless of goal
A* Search (Focused Directional)
. . . . . . . . ◯ . . . [S] ◯ ◯ ◯ . . . ◯ ◯ ◯ [G] . . . . ◯ * Heuristic guides search toward goal
💡 POINT: The A* Evaluation Function
The A* algorithm always prioritizes expanding the node n that has the lowest total evaluation score f(n):
f(n) = g(n) + h(n)
  • g(n): The exact cumulative movement cost from the start node to current node n.
  • h(n): The heuristic estimated remaining cost from node n to the goal.

By prioritizing tiles that are statistically closer to the destination, A* drastically prunes dead-end branches.

Chapter 02 Three Implementation Steps — The Search Pipeline

When building pathfinding in a custom game engine or TypeScript codebase, the architecture boils down to three sequential phases:

1
Convert Grid Map to Graph Adjacency Data

Parse the 2D tile array (walkable tiles 0, walls 1) into neighbor graph edges.

2
Extract Candidates via Priority Queue (Binary Heap)

Use an efficient min-heap data structure to pop the candidate with minimal f(n) in logarithmic time.

3
Trace Back Parent Pointers Upon Reaching Goal

Follow the cameFrom mapping backwards from goal to start to produce the continuous movement path.

Data Structure Trade-off Comparison

The choice of collection structure in your inner exploration loop can alter frame times by two orders of magnitude:

✕ Bad: Re-sorting native Array on each push

Calling array.sort() repeatedly degrades complexity to O(N log N) per step, causing immediate frame drops.

Complexity: O(V² log V)
◯ Good: Binary Min-Heap

Insertions and minimum extractions run in strict O(log N) time, maintaining a solid 60 FPS even across vast open maps.

Complexity: O(E + V log V)

// Core A* Search Routine
export function findShortestPath(start: Node, goal: Node): Node[] {
  const openSet = new MinHeap<Node>((a, b) => a.fScore - b.fScore);
  const cameFrom = new Map<Node, Node>();

  start.gScore = 0;
  start.fScore = heuristic(start, goal);
  openSet.push(start);

  while (!openSet.isEmpty()) {
    const current = openSet.pop()!;
    if (current === goal) {
      return reconstructPath(cameFrom, current); // Success
    }
    // Expand neighbors and update scores...
  }
  return []; // Unreachable target
}
⚠️ CAUTION: Admissibility of the Heuristic Function
If your heuristic estimate h(n) ever exceeds the actual remaining distance, the algorithm loses its optimality guarantee. On 4-way orthogonal grid maps without diagonal steps, always choose Manhattan Distance.

Quick reference matrix for selecting the right search algorithm:

📚 COLUMN: Scaling from Game AI to Discrete Optimization (MILP)
When games evolve from single-unit navigation to complex coordination—such as "routing 20 squads without traffic jams" or "scheduling 24-hour guard shifts without staff burnout"—pathfinding alone is insufficient. This is where Mixed-Integer Linear Programming (MILP) solvers (like HiGHS and GLPK) shine: by declaring rules as mathematical equations, the solver computes the global optimum automatically!

Chapter 01 迷宫追逐战 — 从 Dijkstra 到 A* 寻路

在动作 RPG 或肉鸽（Roguelike）游戏中，怪物总能灵巧地避开墙壁、陷阱直奔玩家而来。支撑这一智能行为的核心技术就是「最短路径寻路算法（Pathfinding）」。

KEY QUESTION / 核心疑问
既然按顺序逐个检查每一个格子最终也能找到最短路径，为什么我们还需要 A* 算法？
广度优先搜索等全量扫描算法会无差别地向所有方向扩散——甚至包括背离目标的方向。在大型地图上，这会导致状态空间急剧爆炸。A* 算法通过引入「启发式估计值（Heuristic）」，将算力集中投向目标方向，从而大幅削减无效探索。
📊 搜索空间扩散范围对比
广度优先搜索 (无差别同心圆扩散)
. . ◯ . . . ◯ ◯ ◯ . ◯ ◯ [S] ◯ ◯ . ◯ ◯ ◯ . [G] . . ◯ . . ※ 不论终点方向，均匀向外扩散
A* 寻路 (启发式导向目标收敛)
. . . . . . . . ◯ . . . [S] ◯ ◯ ◯ . . . ◯ ◯ ◯ [G] . . . . ◯ ※ 借助估算代价大幅聚焦于目标侧
💡 POINT : A* 算法的评估函数
A* 算法在每一步探索中，总是优先挑选综合评分 f(n) 最小的节点 n：
f(n) = g(n) + h(n)
  • g(n)：从起点到当前节点 n 的「实际移动代价」
  • h(n)：从节点 n 到终点的「启发式估计剩余代价（如直线或折线距离）」

正是凭借这种「朝目标靠近可能性更高」的优先机制，A* 规避了大量毫无意义的死胡同探索。

Chapter 02 三步落地 — 迷宫寻路的核心流程

在游戏引擎或前端 TypeScript 中实现寻路算法时，整体流程可清晰划分为三个阶段：

1
将网格地图转换为图节点与连边

从二维数组地图数据（可通行地块 0、障碍墙体 1）构建相邻节点的邻接关系。

2
利用优先队列（二叉堆）高效提取最小候选

通过二叉最小堆在对数时间内弹出 f(n) 最小的节点，极速决策下一个探索目标。

3
到达终点后回溯父指针重建最优路径

从终点倒序遍历 cameFrom 映射表直抵起点，生成最终平滑的移动路线。

数据结构选型对性能的影响

内层探索循环中所使用的数据结构，往往会造成上百倍的性能差距：

✕ NG : 每次向普通数组插入后调用 sort()

频繁调用 array.sort() 会使单步复杂度飙升至 O(N log N)，在大型地图上导致画面严重掉帧。

计算复杂度: O(V² log V)
◯ OK : 最小二叉堆 (Binary Heap)

元素插入和提取最小值仅需 O(log N)，即使在千格大地图上也能稳健维持 60 FPS 实时计算。

计算复杂度: O(E + V log V)

// A* 寻路核心逻辑
export function findShortestPath(start: Node, goal: Node): Node[] {
  const openSet = new MinHeap<Node>((a, b) => a.fScore - b.fScore);
  const cameFrom = new Map<Node, Node>();

  start.gScore = 0;
  start.fScore = heuristic(start, goal);
  openSet.push(start);

  while (!openSet.isEmpty()) {
    const current = openSet.pop()!;
    if (current === goal) {
      return reconstructPath(cameFrom, current); // 重建并返回路径
    }
    // 扩展相邻节点并更新代价分数...
  }
  return []; // 目标不可达
}
⚠️ CAUTION : 启发式函数的「可采纳性（Admissibility）」
若预估代价 h(n) 超过了实际物理距离，算法的最优性保证将被打破。在无对角线行进的正交四向网格中，务必采用曼哈顿距离（Manhattan Distance）。
