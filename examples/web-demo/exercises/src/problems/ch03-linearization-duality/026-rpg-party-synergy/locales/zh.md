# #026. RPG 冒险小队协同最大化

<!-- section:scenario -->
一位冒险者正从候选英雄名单中招募一支地下城冒险小队。每位英雄都有各自的基础战力和招募费用（金币），队伍必须满足以下规则：

- **预算上限**：所有入队英雄的招募费用总和不得超过金币预算上限。
- **人数上限**：入队英雄数量不得超过小队最大名额。
- **配对交互**：当名单中的某对英雄同时入队时，会触发协同加成（正值）或互斥惩罚（负值）。

请决定招募哪些英雄并输出各配对的同时入队指示变量，在满足上述规则的前提下**最大化小队总战力（个人基础战力加上配对加减成）**。

<!-- section:io -->
### 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `power` | `number[]` | 各英雄的基础战力 |
| `costs` | `number[]` | 各英雄的招募费用（金币） |
| `budget` | `number` | 总预算上限（金币） |
| `maxPartySize` | `number` | 小队最大人数上限 |
| `pairs` | `number[][]` | 交互对列表 `[i, j, s]`（`i`、`j` 为从 0 开始的英雄下标，$s > 0$ 为协同加成，$s < 0$ 为互斥惩罚） |

### 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `selected` | `number[]` | 各英雄的 0-1 招募选择向量 $x_i$ |
| `pairProducts` | `number[]` | 各配对的同时入队乘积 $w_k = x_i x_j$ |
| `totalValue` | `number` | 最大化后的小队总战力 |

<!-- section:example -->
**输入示例**

```json
{
  "power": [40, 35, 30, 25],
  "costs": [25, 25, 20, 15],
  "budget": 60,
  "maxPartySize": 2,
  "pairs": [
    [0, 1, 25],
    [1, 2, -20],
    [0, 3, 10],
    [2, 3, 15]
  ]
}
```

**输出示例**

```json
{
  "selected": [1, 1, 0, 0],
  "pairProducts": [1, 0, 0, 0],
  "totalValue": 100
}
```

招募英雄 0 与 1（[1, 1, 0, 0]）占用 $2 \le 2$ 个名额、花费 $25 + 25 = 50 \le 60$ 金币，仅激活配对 (0, 1)（`pairProducts` 为 [1, 0, 0, 0]），小队总战力为 $40 + 35 + 25 =$ **100**。

<!-- section:hint1 -->
为每位候选英雄声明一个表示是否招募的二元决策变量，并为每对交互组合声明一个取值在 0 到 1 之间的连续辅助变量。由于英雄选择只能取 0 或 1，只要加上将其与英雄选择耦合的线性约束，配对变量即使声明为连续变量也会自动精确取 0 或 1。

<!-- section:hint2 -->
在加入预算与人数上限约束后，用三条不等式构成的 McCormick（Fortet）包络线性化每对乘积 $w_k = x_i x_j$：由两名英雄分别限制的两条上界用于防止在未同时入队时虚领协同加成（$s > 0$），而一条下界则在两人同时入队时迫使 $w_k = 1$，避免逃避互斥惩罚（$s < 0$）。当交互权重正负混合时，上下两个方向缺一不可。返回整数结果时请对 `pairProducts` 进行取整。
