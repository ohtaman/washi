# #057. 主题乐园分组游玩规划（带时间窗）

<!-- section:scenario -->
最多 `maxGroups` 个小组在开园时间从主题乐园入口（地点 0）出发，必须恰好游览所有指定项目一次，并在闭园时间前返回入口。每个游乐项目都有允许开始的时间窗（从开放到截止）以及游玩时长；若提前到达可等待至开放时间，但严禁超过截止时间才开始。

请规划最多 `maxGroups` 条游览路线，在满足所有时间窗与闭园时间的前提下，**最小化总步行移动时间**。

<!-- section:io -->
### 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `travelTimes` | `number[][]` | $(n+1) \times (n+1)$ 步行时间矩阵（0 为乐园入口，1..n 为游乐项目） |
| `earliest` | `number[]` | 每个地点的最早允许开始时间（`earliest[0] = 0`） |
| `latest` | `number[]` | 各项目的最晚允许开始时间；`latest[0]` 为闭园返回期限 |
| `visitDurations` | `number[]` | 每个地点的游玩时长（`visitDurations[0] = 0`） |
| `maxGroups` | `number` | 从入口 0 出发的小组数量上限 |

### 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `itineraries` | `number[][]` | 各小组的游览路径列表，每条均以 0 起止（`[0, ..., 0]`） |
| `totalCost` | `number` | 最小化的所有小组步行总时间 |

<!-- section:example -->
**输入**

```json
{
  "travelTimes": [
    [0, 4, 7, 5, 3],
    [4, 0, 5, 4, 6],
    [7, 5, 0, 4, 7],
    [5, 4, 4, 0, 5],
    [3, 6, 7, 5, 0]
  ],
  "earliest": [0, 12, 5, 2, 14],
  "latest": [45, 18, 14, 9, 24],
  "visitDurations": [0, 3, 2, 3, 2],
  "maxGroups": 2
}
```

**输出**

```json
{
  "itineraries": [
    [0, 1, 0],
    [0, 3, 2, 4, 0]
  ],
  "totalCost": 27
}
```

小组 `[0, 1, 0]` 在项目 1 等待至 `t = 12` 开始并在 `19 <= 45` 返回（步行 8），`[0, 3, 2, 4, 0]` 依次在 `t = [5, 12, 21]` 开始并在 `26 <= 45` 返回（步行 19），总步行时间为 $8 + 19 =$ **27**。

<!-- section:hint1 -->
为每对不同地点建立二元转移变量，为每个地点建立上下界为 `[earliest[i], latest[i]]` 的连续开始时间变量，并为各游乐项目引入辅助游览顺位势能变量。固定入口出发时间，约束每个项目入度与出度均为 1，并使入口的平衡度数不超过 `maxGroups`。

<!-- section:hint2 -->
沿激活转移 `(i, j)` 用紧凑的 Big-M 不等式（$t_i + s_i + d_{ij} - t_j \le M_{ij}(1 - x_{ij})$，其中 $M_{ij} = \max(0, l_i + s_i + d_{ij} - e_j)$）衔接开始时间，并对返回弧 `(i, 0)` 施加闭园时间约束。注意若存在耗时为零的同址项目（`visitDurations + travelTimes == 0`），仅靠时间单调性无法阻止零耗时项目子环，因此也需要在项目弧上加入 MTZ 顺位约束。
