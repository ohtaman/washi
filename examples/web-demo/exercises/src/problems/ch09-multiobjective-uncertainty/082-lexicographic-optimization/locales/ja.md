# #082. 2段階辞書式最適化（レキシコグラフィック最適化）

<!-- section:scenario -->
緊急対応センターでは、限られた人員枠の範囲内で複数の候補ユニットから稼働させる組合せ（0-1 選択）を決定し、目標需要量をカバーします。需要充足はコスト削減よりも厳格に優先されるため、目的を 2 段階の辞書式順序で最適化します。

まず第 1 段階で人員枠のもとでの最小未充足需要を求め、次に第 2 段階で未充足需要を「第 1 段階の最小値 ＋ 許容劣化スラック」以下に抑えたうえで、二次的な運用コストの合計を最小化してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `coverage` | `number[]` | 各ユニットを稼働させたときの供給能力 |
| `crews` | `number[]` | 各ユニットの必要人員数 |
| `opCosts` | `number[]` | 各ユニットの副次的な運用コスト |
| `maxCrews` | `number` | 総必要人員数のハード上限 |
| `targetDemand` | `number` | 目標需要量 |
| `slack` | `number` | 第 1 段階最小値から許容する追加未充足スラック（厳格なら `0`） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `selected` | `number[]` | 各ユニットの稼働選択（`0` または `1`） |
| `obj1` | `number` | 実際の未充足需要（`max(0, targetDemand - covered)`） |
| `obj2` | `number` | 最小化された二次運用コスト |

<!-- section:example -->
**入力例**

```json
{
  "coverage": [10, 12, 15, 8],
  "crews": [2, 3, 4, 2],
  "opCosts": [300, 180, 260, 120],
  "maxCrews": 6,
  "targetDemand": 22,
  "slack": 0
}
```

**出力例**

```json
{
  "selected": [0, 0, 1, 1],
  "obj1": 0,
  "obj2": 380
}
```

ユニット 2・3 を選ぶと人員数 $4 + 2 = 6 \le 6$ で供給能力 $15 + 8 = 23 \ge 22$（`obj1 = 0`）を満たし、運用コストは $260 + 120 =$ **380** となります。


<!-- section:hint1 -->
ユニット選択のバイナリ変数と人員上限の制約を用いて、2 つの混合整数計画問題（MIP）を順番に解きます。第 1 段階では非負連続の不足量変数を導入して達成可能な最小の未充足需要を求め、第 2 段階ではその最小不足量に許容スラックを加えた上限をハード制約として固定したうえで、二次的な運用コストを最小化します。

<!-- section:hint2 -->
2 つの目的を大きな重みで 1 つにまとめる単一目的の重み付け和は、厳密な優先順位や許容劣化幅 `slack` を正しく反映できないため避けてください。第 2 段階では $\text{covered} \ge \text{targetDemand} - (\text{bestObj1} + \text{slack})$ を課し、返却する `obj1` は第 2 段階の選択結果から `Math.max(0, targetDemand - covered)` として算出します。バイナリ変数の値は WaSHI では `Math.round(v.value!)`、PuLP では `round(pulp.value(v))` で整数化してください。
