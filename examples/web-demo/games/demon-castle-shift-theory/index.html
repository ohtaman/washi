数理最適化（MILP）モデリング解説

『魔王城の24時間警備シフト』の裏側：
勤務スケジューリング問題（NSP）と論理条件の線形化

対象読者：混合整数線形計画（MIP）の基礎（二値変数・線形不等式・目的関数）をご存じの方。
現実の病院（ナース・スケジューリング）やコールセンター・警備現場で用いられるシフト最適化モデルが、ゲーム内の「夜勤明け日勤の禁止」「連勤上限」「ペア相性（二次項の線形化）」「単独夜勤の禁止」にどう1対1対応しているのかを解説します。

1. 警備シフトパズルと勤務スケジューリング問題（NSP）

オペレーションズ・リサーチ（OR）の代表的な応用分野にナース・スケジューリング問題（Nurse Scheduling Problem; NSP）や人員配置問題（Staff Rostering）があります。『魔王城の24時間警備シフト』は、この古典的かつ実用的なMILPモデルをそのままファンタジー世界の拠点防衛パズルに翻案したものです。

ゲームの要素 実務のシフト最適化での対応物 数理モデル上の表現
警備モンスター m ∈ M スタッフ・看護師・警備員 添字集合 M（各人のスキル・体力上限を持つ）
日付 d ∈ D と昼番/夜番 s ∈ {day, night} 計画期間の各日・各シフト区分 二値決定変数 x_{m,d,day}, x_{m,d,night} ∈ {0, 1}
勇者軍の襲来戦力 R_{d,s} 時間帯ごとの必要スキル量・需要予測 被覆制約（Covering Constraint）の右辺定数
夜番→翌日昼番の禁止 勤務間インターバル規制（夜勤明け日勤禁止） 隣接シフト間の排他制約 x_{m,d,night} + x_{m,d+1,day} <= 1
連勤上限・週出勤上限・指定休 労働基準ルール・公休・希望休 スライディング・ウィンドウ制約と変数固定
プルルの「夜間単独配置の禁止」 新人スタッフの単独夜勤禁止（OJT同伴制約） 含意制約（Implication Constraint）
仲良しコンビ・不仲ペア ペア配置推奨・同時配置回避 積 x_A * x_B の McCormick 線形化変数 p_{A,B,d,s}

2. 決定変数と労務制約の定式化

計画対象の日集合を D = {0, 1, …, T-1}、出撃可能な魔物の集合を M とします。各魔物 m ∈ M・各日 d ∈ D に対して、昼番に入るかどうかの二値変数 day_{m,d} ∈ {0, 1} と、夜番に入るかどうかの二値変数 night_{m,d} ∈ {0, 1} を定義します（両方 0 ならその日は「休み」です）。

労務・インターバル制約（すべての魔物 m ∈ M について） (1) 1日1シフトまで:         day_{m,d} + night_{m,d} <= 1            (∀d ∈ D)
(2) 夜番→翌日昼番の禁止:    night_{m,d} + day_{m,d+1} <= 1          (∀d ∈ {0, …, T-2})
(3) 週あたり最大出勤日数:    Σ_{d ∈ D} (day_{m,d} + night_{m,d}) <= W_m
(4) 指定休（希望休）:        day_{m,d} + night_{m,d} == 0            (∀(m, d) ∈ OffRequests)

最大連勤日数制約（スライディング・ウィンドウ法）

たとえば「古竜ドラゴは最大 L_m = 1 連勤まで（＝1日働いたら翌日は必ず休み）」「ウェアウルフのフェンリルは最大 L_m = 3 連勤まで」といった連勤制限は、幅 L_m + 1 日のスライディング・ウィンドウを1日ずつずらしながら、「連続するどの L_m + 1 日間を切り取っても、その中の出勤日数は最大 L_m 日以下である（＝最低1日は休みがある）」と書けます。

スライディング・ウィンドウによる連勤上限（幅 L_m + 1） Σ_{k = 0}^{L_m} (day_{m, start + k} + night_{m, start + k}) <= L_m    (∀start ∈ {0, …, T - L_m - 1})
💡 なぜスライディング・ウィンドウが有効なのか 「何連勤目か」を数える状態変数や非線形な条件分岐を一切使わずに、純粋な線形不等式だけで任意の連勤上限 L_m を漏れなく表現できます。しかもLP緩和が比較的タイトになるため、MILPソルバーの分枝限定法が高速に収束します。

3. 論理条件の線形化（1）：「新米スライムの夜間単独配置禁止」

ゲーム中盤から登場する新米スライムのプルルには、「夜番に入るときは1人きりにせず、必ず他の誰かと一緒に配置しなければならない」というルールがあります（実務のシフト表でも「新人看護師は夜勤に単独配置しない」という全く同じ制約が頻出します）。

論理式で書くと「もし night_{pururu, d} == 1 ならば、Σ_{m ≠ pururu} night_{m, d} >= 1」という含意（Implication）になりますが、二値変数の性質を使うと、たった1本の線形不等式に変換できます。

同伴配置（単独夜勤禁止）の線形不等式 night_{pururu, d} - Σ_{m ∈ M \ {pururu}} night_{m, d} <= 0    (∀d ∈ D)

実際、他のメンバーが誰も夜番に入っていない（Σ_{m ≠ pururu} night_{m, d} == 0）ときは、night_{pururu, d} <= 0 となってプルルも配置できなくなり、逆に他の誰か1人でも夜番に入っていれば（和が 1 以上）、night_{pururu, d} <= 1 となってプルルも配置可能になります。

4. 論理条件の線形化（2）：ペア相性（二次項 x_A * x_B）の線形化

さらにゲーム性を深めているのが、メンバー間のペア相性（連携ボーナスと同番拒否）です。

  • 仲良し・連携ペア（Δ_{A,B} > 0）：同じシフト (d, s) に A と B の両方が入ると、連携ボーナスで防衛力と士気が +Δ_{A,B} 上がる。
  • 不仲・同番拒否ペア（Δ_{A,B} < 0）：同じシフトに A と B が一緒に入ると、反発して防衛力と士気が Δ_{A,B} 下がる。

これを素直に式にすると、A の配置変数 x_{A,d,s} と B の配置変数 x_{B,d,s} の積（二次項）x_{A,d,s} * x_{B,d,s} が現れてしまい、そのままでは線形計画（MILP）になりません。

補助二値変数 pair_{A,B,d,s} ∈ {0, 1} による標準線形化（Fortet / McCormick 線形化）

そこで、「A と B が同じ枠 (d, s) に同時配置されたときだけ 1 になる補助二値変数 pair_{A,B,d,s} ∈ {0, 1}」を導入し、次の3本の線形不等式で積 x_A * x_B と完全に等価にします。

二値変数の積 pair == x_A * x_B を表す3本の線形不等式 (a) pair_{A,B,d,s} - x_{A,d,s} <= 0            : A がいない(0)なら pair も必ず 0
(b) pair_{A,B,d,s} - x_{B,d,s} <= 0            : B がいない(0)なら pair も必ず 0
(c) x_{A,d,s} + x_{B,d,s} - pair_{A,B,d,s} <= 1 : A と B が両方いる(1+1=2)なら pair は必ず 1
✨ 正のシナジーも負のペナルティもこの3本で厳密に表現できる理由 もし正のボーナス（Δ_{A,B} > 0）だけなら式(a)・(b)の上界だけでも目的関数が自然に pair = 1 を選びますが、負のペナルティ（Δ_{A,B} < 0、不仲ペア）がある場合はソルバーがペナルティを逃れようとして pair = 0 に下げようとします。そこに式(c)の下界 pair >= x_A + x_B - 1 があることで、「2人を同時に置いたら必ず pair = 1 になって減点を受ける」ことが厳密に強制されます。

5. 防衛力被覆制約と「別解の列挙（No-Good Cut）」

各時間帯 (d, s) において、個人の実効防衛力 P_{m,s} とペア相性補正の合計が必要防衛力 R_{d,s} 以上になるよう被覆制約（Covering Constraint）を課し、全期間を通じた魔王城の総士気（Morale）を最大化します。

各襲来枠 (d, s) の防衛力・最低人数制約と目的関数 防衛力被覆:   Σ_{m ∈ M} P_{m,s} * x_{m,d,s} + Σ_{(A,B)} Δ_{A,B} * pair_{A,B,d,s} >= R_{d,s}
最低人数:     Σ_{m ∈ M} x_{m,d,s} >= N_{d,s}
目的関数:     maximize   1000 + Σ_{d,s} ( Σ_{m} morale_{m,s} * x_{m,d,s} + Σ_{(A,B)} Δ_{A,B} * pair_{A,B,d,s} )

複数の最適シフト案を次々と提案する「No-Good Cut」

実務でもゲームでも、「条件を満たすシフト表を1つだけでなく、別のパターンも見てみたい」という場面があります。すでに得られた解の 1 の変数集合を S_1、0 の変数集合を S_0 としたとき、以下のNo-Good Cut（整数カット）を1本追加して再求解すると、直前のシフト表と最低1マス以上異なる次善解（または同点の別最適解）を瞬時に得ることができます。 

// 直前のシフト割当と完全に同一の0-1パターンだけを禁止する No-Good Cut
// Σ_{v ∈ S_1} v - Σ_{u ∈ S_0} u <= |S_1| - 1
m.constraint(
  expr`${sum(activeOnes)} - ${sum(activeZeros)} <= ${activeOnes.length - 1}`,
  "forbid_exact_schedule"
);

Mathematical Optimization (MILP) Formulation Guide

Behind "Demon Castle 24-Hour Guard Shift":
Nurse Scheduling (NSP) and Linearization of Logical Rules

Target Audience: Readers familiar with the basics of Mixed-Integer Linear Programming (binary variables, linear inequalities, and objective functions).
This article explains how real-world staff rostering and nurse scheduling models map directly onto the game's mechanics: rest intervals after night shifts, consecutive work limits, rookie supervision rules, and McCormick linearization of pairwise synergies and conflicts.

1. Guard Shift Puzzle and the Nurse Scheduling Problem (NSP)

One of the most widely deployed applications of Operations Research (OR) is the Nurse Scheduling Problem (NSP) or Staff Rostering. "Demon Castle 24-Hour Guard Shift" adapts this practical MILP formulation into a fantasy castle defense puzzle.

Game Element Real-World Shift Scheduling Counterpart Mathematical Model Representation
Guard Monster m ∈ M Staff member, nurse, security guard Index set M (each with skill levels and stamina caps)
Day d ∈ D and Shift s ∈ {day, night} Planning horizon days and shift slots Binary decision variables x_{m,d,day}, x_{m,d,night} ∈ {0, 1}
Hero Army Raid Power R_{d,s} Required skill coverage / forecasted demand per slot Right-hand side constant of the Covering Constraint
No Day Shift After a Night Shift Minimum rest interval between shifts Pairwise exclusion x_{m,d,night} + x_{m,d+1,day} <= 1
Consecutive / Weekly Caps & Days Off Labor regulations, weekly caps, requested PTO Sliding-window constraints and variable fixing
Pururu's "No Solo Night Shift" Junior staff supervision (no solo night duty) Logical implication constraint
Synergy Pairs (+100) & Clashes (-150) Preferred pairing / incompatible staff avoidance McCormick linearization variable p_{A,B,d,s} for x_A * x_B

2. Decision Variables and Labor Rule Formulation

Let D = {0, 1, …, T-1} denote the planning days and M denote the on-duty guard roster. For each guard m ∈ M and day d ∈ D, we define binary variables day_{m,d} ∈ {0, 1} and night_{m,d} ∈ {0, 1} (if both are 0, guard m rests on day d).

Labor & Rest Interval Constraints (for all m ∈ M) (1) At most 1 shift per day:      day_{m,d} + night_{m,d} <= 1            (∀d ∈ D)
(2) No Night → Next-Morning Day:   night_{m,d} + day_{m,d+1} <= 1          (∀d ∈ {0, …, T-2})
(3) Weekly shift cap:             Σ_{d ∈ D} (day_{m,d} + night_{m,d}) <= W_m
(4) Requested day off (PTO):      day_{m,d} + night_{m,d} == 0            (∀(m, d) ∈ OffRequests)

Maximum Consecutive Working Days (Sliding-Window Formulation)

To enforce rules such as "Elder Dragon Drago can work at most L_m = 1 consecutive day (must rest the day after working)" or "Werewolf Fenrir can work at most L_m = 3 consecutive days," we slide a window of length L_m + 1 days across the horizon. Within every contiguous window of L_m + 1 days, the guard can work at most L_m days (guaranteeing at least one rest day inside the window):

Sliding-Window Consecutive Work Limit (Window Width L_m + 1) Σ_{k = 0}^{L_m} (day_{m, start + k} + night_{m, start + k}) <= L_m    (∀start ∈ {0, …, T - L_m - 1})
💡 Why the Sliding-Window Formulation Is Effective It expresses arbitrary consecutive-day limits L_m using pure linear inequalities without auxiliary state counters or non-linear branching. It also yields a tight LP relaxation, allowing branch-and-bound solvers to converge rapidly.

3. Linearizing Logic (Part 1): Rookie Slime's "No Solo Night Duty"

Rookie guards like Pururu the Slime have a supervision rule: "She cannot be assigned to a night shift alone; at least one other colleague must work the same night shift." (This mirrors hospital rostering rules where first-year nurses cannot staff a night ward solo.)

Logically, this is the implication night_{pururu, d} == 1 ⇒ Σ_{m ≠ pururu} night_{m, d} >= 1. Because all variables are binary, it translates into a single linear inequality:

Linear Inequality for Supervised Night Duty night_{pururu, d} - Σ_{m ∈ M \ {pururu}} night_{m, d} <= 0    (∀d ∈ D)

When no other guard is assigned to night duty on day d (the sum is 0), the inequality forces night_{pururu, d} <= 0. As soon as at least one colleague is assigned (the sum is 1 or more), night_{pururu, d} <= 1 allows Pururu to join the shift.

4. Linearizing Logic (Part 2): Pairwise Synergies & Conflicts (x_A * x_B)

Guard chemistry plays a central role in building a strong defense line:

  • Synergy Pairs (Δ_{A,B} > 0): Assigning both A and B to the same slot (d, s) grants a +Δ_{A,B} (+100) teamwork bonus to defense power and morale.
  • Incompatible Pairs (Δ_{A,B} < 0): Assigning both A and B to the same slot triggers a Δ_{A,B} (-150) conflict penalty.

Written directly, this introduces the quadratic product x_{A,d,s} * x_{B,d,s} of two binary variables, which is non-linear.

Standard Linearization via Auxiliary Binary Variable pair_{A,B,d,s} ∈ {0, 1} (Fortet / McCormick)

We introduce an auxiliary binary variable pair_{A,B,d,s} ∈ {0, 1} that equals 1 if and only if both A and B are assigned to slot (d, s), governed by three linear inequalities:

Three Linear Inequalities Enforcing pair == x_A * x_B (a) pair_{A,B,d,s} - x_{A,d,s} <= 0            : If A is absent (0), pair must be 0
(b) pair_{A,B,d,s} - x_{B,d,s} <= 0            : If B is absent (0), pair must be 0
(c) x_{A,d,s} + x_{B,d,s} - pair_{A,B,d,s} <= 1 : If both A and B are present (1+1=2), pair must be 1
✨ Why Both Upper and Lower Bounds Matter Here For a positive synergy bonus (Δ_{A,B} > 0), upper bounds (a) and (b) alone would suffice because maximization naturally pushes pair up to 1. Conversely, for a negative conflict penalty (Δ_{A,B} < 0), the solver tries to set pair = 0 to dodge the penalty; inequality (c) provides the lower bound pair >= x_A + x_B - 1 that forces pair = 1 whenever both guards share a slot.

5. Defense Coverage Constraints and Alternative Solutions (No-Good Cuts)

In each slot (d, s), the sum of individual effective defense powers P_{m,s} plus pairwise modifiers must cover the required power R_{d,s} and minimum headcount N_{d,s}, while maximizing total castle morale:

Slot Coverage Constraints and Objective Function Defense Coverage:   Σ_{m ∈ M} P_{m,s} * x_{m,d,s} + Σ_{(A,B)} Δ_{A,B} * pair_{A,B,d,s} >= R_{d,s}
Minimum Staff:      Σ_{m ∈ M} x_{m,d,s} >= N_{d,s}
Objective:          maximize   1000 + Σ_{d,s} ( Σ_{m} morale_{m,s} * x_{m,d,s} + Σ_{(A,B)} Δ_{A,B} * pair_{A,B,d,s} )

Enumerating Alternative Rosters with a "No-Good Cut"

In both real-world scheduling and puzzle design, we often want to inspect alternative valid schedules. Given an existing binary solution with active ones S_1 and zeros S_0, adding a single No-Good Cut (Canonical Integer Cut) excludes that exact assignment pattern and finds the next-best (or tied optimal) schedule differing in at least one cell: 

// No-Good Cut forbidding the exact previous 0-1 schedule assignment
// Σ_{v ∈ S_1} v - Σ_{u ∈ S_0} u <= |S_1| - 1
m.constraint(
  expr`${sum(activeOnes)} - ${sum(activeZeros)} <= ${activeOnes.length - 1}`,
  "forbid_exact_schedule"
);

数学规划（MILP）建模解说

《魔王城24小时警备排班》背后的数学模型：
护士排班问题（NSP）与逻辑条件的线性化

适合读者：了解混合整数线性规划（MIP）基础（0-1变量、线性不等式与目标函数）的读者。

1. 警备排班解谜与护士排班问题（NSP）

运筹学（OR）中最具代表性的应用领域之一便是护士排班问题（Nurse Scheduling Problem; NSP）与人员排班问题（Staff Rostering）。《魔王城24小时警备排班》正是将这一经典且实用的 MILP 模型改编成了奇幻世界背景下的据点防卫益智游戏。

2. 决策变量与劳务规则的数学建模

设计划周期的日期集合为 D = {0, 1, …, T-1}，可出勤的魔物集合为 M。对每位成员 m ∈ M 与每一天 d ∈ D，定义是否上白班的 0-1 变量 day_{m,d} ∈ {0, 1} 与是否上夜班的 0-1 变量 night_{m,d} ∈ {0, 1}（若两者均为 0，则当天为“休息”）。

劳务与班次间隔约束（对所有成员 m ∈ M） (1) 每天最多一个班次:         day_{m,d} + night_{m,d} <= 1            (∀d ∈ D)
(2) 禁止夜班次日接白班:       night_{m,d} + day_{m,d+1} <= 1          (∀d ∈ {0, …, T-2})
(3) 每周最大出勤天数:         Σ_{d ∈ D} (day_{m,d} + night_{m,d}) <= W_m
(4) 指定休假（固定排休）:     day_{m,d} + night_{m,d} == 0            (∀(m, d) ∈ OffRequests)

最大连续工作天数约束（滑动窗口法）

例如“古龙德拉戈最多连续工作 L_m = 1 天（工作1天后次日必须休息）”、“狼人芬里尔最多连续工作 L_m = 3 天”这类限制，可以通过长度为 L_m + 1 天的滑动窗口（Sliding Window）逐日平移来表达：“在任意连续的 L_m + 1 天窗口内，出勤天数总和最多不超过 L_m 天（即窗口内至少有1天休息）”。

滑动窗口表达的连勤上限（窗口宽度 L_m + 1） Σ_{k = 0}^{L_m} (day_{m, start + k} + night_{m, start + k}) <= L_m    (∀start ∈ {0, …, T - L_m - 1})
💡 为什么滑动窗口写法非常实用 它无需引入记录“当前是第几天连勤”的状态变量或非线性条件分支，仅用纯线性不等式就能严密表达任意连勤上限 L_m，且具有较紧的 LP 松弛界，有助于分支定界求解器快速收敛。

3. 逻辑条件的线性化（一）：“新人史莱姆禁止夜间单独值班”

游戏中期加入的新人史莱姆普露露有一条特殊规则：“安排夜班时不能让她独自一人，必须至少有一位其他同伴一起上夜班”（在医院排班中同样常见“新人护士不得单独值夜班”的带教约束）。

用逻辑式表示即蕴含关系：“若 night_{pururu, d} == 1，则 Σ_{m ≠ pururu} night_{m, d} >= 1”。利用 0-1 变量的性质，只需一条线性不等式即可完成转换：

同伴陪护（禁止单独夜班）的线性不等式 night_{pururu, d} - Σ_{m ∈ M \ {pururu}} night_{m, d} <= 0    (∀d ∈ D)

当其他成员都没有安排当天夜班（求和为 0）时，不等式强制 night_{pururu, d} <= 0，普露露无法单独排入夜班；反之只要有任意一位前辈在夜班（求和 >= 1），night_{pururu, d} <= 1 即允许普露露一同出勤。

4. 逻辑条件的线性化（二）：搭档相性（二次项 x_A * x_B）的线性化

进一步丰富排班策略的是成员之间的搭档相性（协同加成与同班排斥）：

  • 默契搭档（Δ_{A,B} > 0）：当 A 与 B 同时排入同一班次 (d, s) 时，触发协同加成，防卫力与士气提升 +Δ_{A,B}（+100）。
  • 不睦组合（Δ_{A,B} < 0）：当 A 与 B 被排入同一班次时，因互相排斥导致防卫力与士气下降 Δ_{A,B}（-150）。

若直接写出数学表达式，会出现两个 0-1 变量的乘积项（二次项）x_{A,d,s} * x_{B,d,s}，导致模型不再是线性规划。

引入辅助 0-1 变量 pair_{A,B,d,s} ∈ {0, 1} 的标准线性化（Fortet / McCormick 线性化）

为此，我们引入辅助 0-1 变量 pair_{A,B,d,s} ∈ {0, 1}（仅当 A 与 B 同时排入班次 (d, s) 时取 1），并用以下3条线性不等式使其与乘积 x_A * x_B 完全等价：

等价表达 0-1 变量乘积 pair == x_A * x_B 的 3 条线性不等式 (a) pair_{A,B,d,s} - x_{A,d,s} <= 0            : 若 A 未出勤(0)，则 pair 必为 0
(b) pair_{A,B,d,s} - x_{B,d,s} <= 0            : 若 B 未出勤(0)，则 pair 必为 0
(c) x_{A,d,s} + x_{B,d,s} - pair_{A,B,d,s} <= 1 : 若 A 与 B 同时出勤(1+1=2)，则 pair 必为 1
✨ 为什么正负相性都能由这 3 条不等式严密刻画 如果只有正加成（Δ_{A,B} > 0），仅靠上界约束 (a)・(b)，最大化目标函数也会自动将 pair 推向 1；但当存在负惩罚（Δ_{A,B} < 0，不睦组合）时，求解器会试图将 pair 设为 0 来逃避扣分。此时下界约束 (c) pair >= x_A + x_B - 1 能够严格强制“只要两人同班，pair 就必须为 1 并扣除 150 点防卫力”。

5. 防卫力覆盖约束与“多解枚举（No-Good Cut）”

在每个时段 (d, s)，个人实际防卫力 P_{m,s} 与搭档相性修正之和必须达到所需防卫力 R_{d,s} 及最低人数 N_{d,s}（覆盖约束），并在此基础上最大化全周期的总士气（Morale）：

各班次 (d, s) 的防卫力/最低人数约束与目标函数 防卫力覆盖:   Σ_{m ∈ M} P_{m,s} * x_{m,d,s} + Σ_{(A,B)} Δ_{A,B} * pair_{A,B,d,s} >= R_{d,s}
最低人数:     Σ_{m ∈ M} x_{m,d,s} >= N_{d,s}
目标函数:     maximize   1000 + Σ_{d,s} ( Σ_{m} morale_{m,s} * x_{m,d,s} + Σ_{(A,B)} Δ_{A,B} * pair_{A,B,d,s} )

生成不同最优排班方案的“No-Good Cut（整数割）”

无论在实际排班还是解谜中，我们常常希望看到不止一种可行排班方案。设已求得的某个解中取值为 1 的变量集合为 S_1，取值为 0 的变量集合为 S_0，只需向模型追加一条 No-Good Cut（整数割）并重新求解，即可排除刚才完全相同的排班表，立即求得至少有1格不同的另一组最优（或次优）排班方案： 

// 仅禁止与上一组排班表完全相同的 0-1 组合的 No-Good Cut
// Σ_{v ∈ S_1} v - Σ_{u ∈ S_0} u <= |S_1| - 1
m.constraint(
  expr`${sum(activeOnes)} - ${sum(activeZeros)} <= ${activeOnes.length - 1}`,
  "forbid_exact_schedule"
);
