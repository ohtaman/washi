# #090. レジリエント計画・復旧統合演習（第9章総合）

<!-- section:scenario -->
電力・供給網の計画担当者は、事前に稼働させる供給ユニットの 0-1 事前契約を決定し、各ユニットの固定確保費を支払います。通常時は各ユニットが公称容量を発揮しますが、契約済みユニットのうち最大 Γ 個までが同時に所定の容量低下を起こしても、残存容量が要求されるロバスト基準値を下回ってはなりません。

その後、既知の確率に従って障害シナリオのいずれかが発生し、各シナリオ固有の需要量と運転不能ユニット（強制停止）が確定します。停止ユニットを避けつつ各シナリオの復旧 0-1 スケジュールを決め、事前契約からの切替ユニット数（ハミング距離）に応じた変更コストと不足需要への弾力ペナルティを含めた「固定費＋期待復旧・欠品コスト」の総和を最小化してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `fixedCosts` | `number[]` | 第 1 段階における各ユニットの固定確保費 |
| `capacities` | `number[]` | 各ユニットの公称供給容量 |
| `dropAmounts` | `number[]` | 事前ロバスト評価で想定する各ユニットの容量低下量 |
| `gamma` | `number` | 第 1 段階容量低下の不確実性予算 $\Gamma \in [0, n]$ |
| `robustMinCap` | `number` | $\Gamma$ 低下時にも確保すべき第 1 段階の最小残存容量 |
| `probs` | `number[]` | 各シナリオ $s$ の生起確率 $p_s$ |
| `demands` | `number[]` | 各シナリオ $s$ で発生する需要量 |
| `offline` | `number[][]` | 各シナリオの運転不能マスク（`1` でユニット $j$ が停止） |
| `disruptionCost` | `number` | 事前契約から状態変更するユニット 1 基あたりの切替コスト |
| `shortfallPenalty` | `number` | 各シナリオの未充足需要 1 単位あたりの弾力ペナルティ |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `committed` | `number[]` | 第 1 段階の事前契約 0-1 ベクトル |
| `recovered` | `number[][]` | 各シナリオ $s$ の復旧 0-1 スケジュール行列（$S \times n$） |
| `totalCost` | `number` | 最小化された固定費＋期待復旧・欠品コスト |

<!-- section:example -->
**入力例**

```json
{
  "fixedCosts": [120, 150, 90, 110],
  "capacities": [18, 22, 12, 16],
  "dropAmounts": [8, 10, 4, 6],
  "gamma": 1,
  "robustMinCap": 28,
  "probs": [0.6, 0.4],
  "demands": [24, 34],
  "offline": [
    [0, 0, 0, 0],
    [0, 1, 0, 0]
  ],
  "disruptionCost": 45,
  "shortfallPenalty": 30
}
```

**出力例**

```json
{
  "committed": [0, 1, 0, 1],
  "recovered": [
    [0, 1, 0, 1],
    [1, 0, 0, 1]
  ],
  "totalCost": 296
}
```

事前契約 `[0, 1, 0, 1]` は固定費 $150 + 110 = 260$ で最悪 1 基低下時の残存容量 $22 + 16 - 10 = 28 \ge 28$ を満たし、シナリオ 0 は変更なし、シナリオ 1 はユニット 1 から 0 へ切替（変更 2 基・容量 $34 \ge 34$）となるため期待総費用は $260 + 0.6(0) + 0.4(45 \times 2) =$ **296** となります。
