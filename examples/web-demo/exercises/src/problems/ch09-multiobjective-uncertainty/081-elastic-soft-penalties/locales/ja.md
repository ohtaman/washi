# #081. 弾力制約計画と優先度つきソフトペナルティ

<!-- section:scenario -->
ある菓子工場では、チョコレート・クッキー・マドレーヌなど複数の菓子製品について、それぞれの生産量（0 以上の連続値、単位：kg）を決定します。工場全体で消費する総稼働時間（時間）は機械能力の上限を超えてはならず、かつ全製品の総生産量は必要な下限（kg）以上である必要があります。

一方で、各製品には目標生産量（kg）が設定されており、目標を下回る不足分には優先度に応じた不足ペナルティが、目標を上回る超過分には超過ペナルティが 1 kg あたり課されます。ハード制約を厳守しつつ、生産コストと目標乖離ペナルティの合計を最小化してください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `unitCosts` | `number[]` | 各製品 1 kg あたりの生産コスト |
| `hours` | `number[]` | 各製品 1 kg あたりの機械稼働時間（時間） |
| `targets` | `number[]` | 各製品の目標生産量（ソフト目標、kg） |
| `shortfallPenalties` | `number[]` | 目標不足 1 kg あたりの優先度別ペナルティ |
| `excessPenalties` | `number[]` | 目標超過 1 kg あたりのペナルティ |
| `machineCap` | `number` | 機械総稼働時間のハード上限（時間） |
| `minTotal` | `number` | 全製品合計生産量のハード下限（kg） |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `quantities` | `number[]` | 各製品の生産量（非負の実数値、kg） |
| `shortfalls` | `number[]` | 各製品の目標に対する不足量（kg） |
| `excesses` | `number[]` | 各製品の目標に対する超過量（kg） |
| `totalCost` | `number` | 最小化された生産コストと目標乖離ペナルティの合計 |

<!-- section:example -->
**入力例**

```json
{
  "unitCosts": [4, 5, 3],
  "hours": [2, 2, 2],
  "targets": [10, 10, 10],
  "shortfallPenalties": [100, 50, 15],
  "excessPenalties": [20, 20, 20],
  "machineCap": 46,
  "minTotal": 0
}
```

**出力例**

```json
{
  "quantities": [10, 10, 3],
  "shortfalls": [0, 0, 7],
  "excesses": [0, 0, 0],
  "totalCost": 204
}
```

`quantities = [10, 10, 3]` は稼働時間 $2(10) + 2(10) + 2(3) = 46 \le 46$ と各製品の目標収支（`shortfalls = [0, 0, 7]`、`excesses = [0, 0, 0]`）を満たし、総コストは $(4 \times 10 + 5 \times 10 + 3 \times 3) + 15 \times 7 =$ **204** となります。


<!-- section:hint1 -->
製品ごとに、生産量・目標不足量・目標超過量を表す 3 種類の決定変数（0 以上の連続変数）を定義します。総機械時間の上限と総生産量の下限は生産量に対するハード制約として課し、各製品の目標値はペナルティ付きのソフト制約として扱います。

<!-- section:hint2 -->
弾力制約のポイントは、不足ペナルティと超過ペナルティがともに非負かつ和が正（$w_j^- + w_j^+ > 0$）であれば、非負の不足スラックと超過スラックを用いた等式で目標を表しても実行不能を防ぎつつ、最適解で少なくとも一方のスラックが自然に 0 になる点です（バイナリ変数は不要です）。WaSHI の `m.continuous(...)` または PuLP の `pulp.LpVariable(..., lowBound=0)` を使って実装してください。
