# #018. 大学の履修計画と前提科目

<!-- section:scenario -->
大学生が来学期に履修する科目の組み合わせを計画しています。各科目には興味スコアがあり、週あたりの学習時間、実験枠、単位数など、複数の負荷区分についてそれぞれ必要な量（負担）が決まっています。

履修計画は次の条件をすべて満たす必要があります。
- **負荷区分ごとの上限**: 学習時間・実験枠・単位数などの合計が、それぞれの上限を超えないこと
- **前提科目**: 前提科目が指定されている科目を履修する場合は、その前提科目もあわせて履修すること
- **時間割の重複**: 時間帯が重なるペアの科目は、同時に両方履修しないこと

すべての条件を満たしながら、**興味スコアの合計を最大化**する履修計画を求めてください。

<!-- section:io -->
### 入力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `interest` | `number[]` | 各候補科目の興味スコア |
| `requirements` | `number[][]` | 負荷行列（`requirements[k][j]` は科目 $j$ が区分 $k$ で使う量） |
| `caps` | `number[]` | 区分 $k$ の上限 |
| `prerequisites` | `number[][]` | `course` を履修するなら `prereq` の履修が必要なペア `[prereq, course]` |
| `timeConflicts` | `number[][]` | 時間割が重複し同時に履修できないペア `[a, b]` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `take` | `number[]` | 各科目を履修するかどうかのバイナリ値（0 または 1） |
| `totalInterest` | `number` | 最大化された興味スコアの合計 |

<!-- section:example -->
**入力例**

```json
{
  "interest": [8, 24, 22, 19, 15],
  "requirements": [
    [5, 6, 4, 5, 3],
    [3, 6, 5, 4, 6]
  ],
  "caps": [13, 13],
  "prerequisites": [[0, 3]],
  "timeConflicts": [[1, 2]]
}
```

**出力例**

```json
{
  "take": [1, 0, 0, 1, 1],
  "totalInterest": 42
}
```

科目 0・3・4 を履修すると、区分 0 は $5 + 5 + 3 = 13 \le 13$、区分 1 は $3 + 4 + 6 = 13 \le 13$ となり、前提 $0 \to 3$ と重複回避 (1, 2) を満たし、興味スコア合計は $8 + 19 + 15 =$ **42** となります。

<!-- section:hint1 -->
各候補科目を0-1のバイナリ変数で表します。このモデルは、負荷区分ごとのナップサック容量制約と、前提科目・時間割重複を表すペアごとの論理制約を組み合わせたものです。

<!-- section:hint2 -->
各行 `requirements[k]` ごとに `caps[k]` を上限とする容量制約を立てます。前提ペア `[prereq, course]` は $x_{\text{course}} \le x_{\text{prereq}}$、時間割重複 `[a, b]` は $x_a + x_b \le 1$ として線形化できます。
