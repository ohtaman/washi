# #023. 正部惩罚线性化（多周期加班排班）

<!-- section:scenario -->
服务中心的运营管理员正在规划多个周期的常规工时（人时），以覆盖预测需求（人时）。

排班方案必须满足以下所有条件：
- **各周期上下限**：每个周期都设有合同规定的最低保底工时和工时上限。
- **总工时上限**：所有周期的常规工时总和不得超过总上限。
- **仅对缺口惩罚**：当某周期常规工时低于需求时，缺口部分需按每人时支付加班或外包惩罚（日元）；超出需求时既无退款也无额外收益。

请在满足所有条件的前提下，找出**最小化常规运营成本与加班惩罚之和（日元）**的排班方案。

<!-- section:io -->
### 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `demands` | `number[]` | 第 $t$ 周期的需求量 $d_t$（人时） |
| `minRegular` | `number[]` | 第 $t$ 周期的最低保底常规工时（人时） |
| `maxRegular` | `number[]` | 第 $t$ 周期的最大常规工时（人时） |
| `regularCosts` | `number[]` | 第 $t$ 周期的单位常规成本（日元/人时） |
| `overtimePenalties` | `number[]` | 第 $t$ 周期未满足需求的单位加班惩罚（日元/人时） |
| `totalRegularCap` | `number` | 全周期常规工时总和的上限（人时） |

### 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `regular` | `number[]` | 各周期的常规工时 $x_t$（人时） |
| `shortage` | `number[]` | 各周期的缺口加班工时 $\max(0, d_t - x_t)$（人时） |
| `totalCost` | `number` | 最小化后的总成本（日元） |

<!-- section:example -->
**输入示例**

```json
{
  "demands": [40, 60, 50],
  "minRegular": [10, 10, 10],
  "maxRegular": [50, 50, 50],
  "regularCosts": [20, 25, 18],
  "overtimePenalties": [50, 45, 55],
  "totalRegularCap": 100
}
```

**输出示例**

```json
{
  "regular": [40, 10, 50],
  "shortage": [0, 50, 0],
  "totalCost": 4200
}
```

常规工时 [40, 10, 50] 合计 $100 \le 100$ 人时且满足各周期上下界，缺口为 [0, 50, 0]，总成本为 $(20 \times 40 + 25 \times 10 + 18 \times 50) + (45 \times 50) =$ **4,200** 日元。


<!-- section:hint1 -->
为每个周期声明一个受限于最低保底常规工时和最大常规工时的连续常规工时变量，以及一个表示由加班弥补的未满足需求的非负连续缺口变量。

<!-- section:hint2 -->
记第 $t$ 周期的需求为 $d_t$、常规工时为 $x_t$、缺口为 $s_t$。要线性化正部缺口 $\max(0, d_t - x_t)$，应使用不等式 $s_t \ge d_t - x_t$ 配合 $s_t \ge 0$，而不是等式——若使用等式，当常规工时因最低保底下限等原因超过需求时会迫使 $s_t < 0$ 而导致无解。还要注意符号方向（是 $d_t - x_t$ 而非 $x_t - d_t$），并别忘了所有周期常规工时总和的上限约束。由于加班惩罚为正且目标最小化总成本，最优解处每个 $s_t$ 会自动紧贴 $\max(0, d_t - x_t)$。
