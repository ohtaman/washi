# Z3 SMT ソルバーエンジン

**Z3** は Microsoft Research が開発した定理証明器・SMT ソルバーです。WaSHI では主に、`Continuous` 変数や小数を含む論理ルール、厳密な数値判定、`unsatCore` による矛盾診断に使います。

---

## インストール

Z3 はオプションの peer dependency です。

```bash
npm install z3-solver
```

---

## Z3・HiGHS・Pumpkin の使い分け

| やりたいこと | おすすめのソルバー | 理由 |
| :--- | :--- | :--- |
| **`Continuous` 変数・小数を含む論理ルール** | **Z3** (`m.check({ solver: "z3" })`) | `implies`・`not`・`and`・`or` の中に実数の不等式を書けます。 |
| **`Continuous` 変数を含むモデルの矛盾診断 (`unsatCore`)** | **Z3** (`m.check({ solver: "z3" })`) | 数値の桁数に影響されず `unsatCore` を抽出できます。 |
| **有界整数・真偽値のみで `COOP`/`COEP` なしにしたい** | **Pumpkin** (`@ohtaman/washi/solvers/pumpkin`) | 同梱・追加依存なしで `SharedArrayBuffer` 不要です。 |
| **LP / MIP / QP の数値最適化** | **HiGHS** (`m.solve()`) | 目的関数の最適化が圧倒的に高速です。 |

> [!TIP]
> 「ルールの整合性チェックや矛盾診断は `Z3`（`m.check()`）、コストの最適化は `HiGHS`（`m.solve()`）」と使い分けるのも有効です。

---

## 基本的な使い方

```typescript
import { Model, expr } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });

const x = model.integer("x", { lb: 0, ub: 10 });
const y = model.integer("y", { lb: 0, ub: 10 });

model.constraint(expr`${x} + ${y} == 15`, "sum_15");
model.constraint(expr`${x} >= 8`, "x_at_least_8");

await model.solve();
console.log(`Status: ${model.status}, x = ${x.value}, y = ${y.value}`);
```

---

## 矛盾診断 (`model.check()`)

`await model.check()` を呼ぶと、制約が満たせるかどうかを判定し、満たせない（`"Unsat"`）場合は矛盾している名前付き制約（`conflicts` / `unsatCore`）を返します。

```typescript
import { Model, expr } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });
const a = model.continuous("a");

model.constraint(expr`${a} >= 10`, "req_A");
model.constraint(expr`${a} <= 5`, "req_B");

const result = await model.check();

if (result.status === "Unsat") {
  console.log("矛盾している制約:", result.conflicts); // model.conflicts / model.unsatCore でも参照可能
  // ["req_A", "req_B"]
}
```

## ブラウザ要件とスレッドの終了

ブラウザでは Z3 が `SharedArrayBuffer` と pthread を使うため、サーバー側で `COOP` / `COEP` ヘッダーの設定が必要です（[Cross-Origin Isolation 設定](../getting-started/cross-origin.md)）。ヘッダーを設定できず、かつ有界整数と真偽値しか使わない場合は [Pumpkin](./pumpkin.md) を利用してください。

Z3 ワーカーで致命的なエラーが起きた場合、実行中の Promise は reject され壊れたランタイムは破棄されるため、次回の `solve()` / `check()` で自動的に新しいインスタンスが起動します。画面のアンマウント時などにワーカーを明示的に終了したい場合は、次を呼び出します。

```typescript
import { killZ3Threads } from "@ohtaman/washi/solvers/z3";

await killZ3Threads();
```
