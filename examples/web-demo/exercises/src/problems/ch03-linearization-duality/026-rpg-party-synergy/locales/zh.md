# #026. RPG 冒险小队协同最大化

<!-- section:scenario -->
一位冒险者正从候选英雄名单中招募一支地下城冒险小队。每位英雄都有各自的基础战力和招募费用，整支小队必须同时满足金币预算上限和队伍人数上限。此外，某些英雄配对在同时入队时会产生交互效应：默契组合提供正的协同加成，而互斥或宿敌组合则会带来负的冲突惩罚。

请在满足预算与人数上限的前提下决定招募哪些英雄，并输出精确的配对激活指示变量，以**最大化小队总战力（个人基础战力加上配对加减成）**。

<!-- section:io -->
### 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `power` | `number[]` | 英雄 $i$ 的基础战力 $p_i$ |
| `costs` | `number[]` | 英雄 $i$ 的招募费用 $c_i$ |
| `budget` | `number` | 金币预算上限 $B$ |
| `maxPartySize` | `number` | 小队最大人数上限 $K$ |
| `pairs` | `number[][]` | 交互对列表 `[i, j, s]`（$s > 0$ 为协同加成，$s < 0$ 为互斥惩罚） |

### 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `selected` | `number[]` | 各英雄的 0-1 招募选择向量 $x_i$ |
| `pairProducts` | `number[]` | 各配对的同时入队乘积 $w_k = x_i x_j$ |
| `totalValue` | `number` | 最大化后的小队总战力 |

<!-- section:example -->
**输入示例**

```json
{
  "power": [40, 35, 30, 25],
  "costs": [25, 25, 20, 15],
  "budget": 60,
  "maxPartySize": 2,
  "pairs": [
    [0, 1, 25],
    [1, 2, -20],
    [0, 3, 10],
    [2, 3, 15]
  ]
}
```

**输出示例**

```json
{
  "selected": [1, 1, 0, 0],
  "pairProducts": [1, 0, 0, 0],
  "totalValue": 100
}
```

招募英雄 0 与 1（[1, 1, 0, 0]）占用 $2 \le 2$ 个名额、花费 $25 + 25 = 50 \le 60$ 金币，仅激活配对 (0, 1)（`pairProducts` 为 [1, 0, 0, 0]），小队总战力为 $40 + 35 + 25 =$ **100**。

<!-- section:hint1 -->
为每位候选英雄声明一个二元决策变量，并为每对交互组合声明一个位于 $[0, 1]$ 的连续辅助变量。由于英雄选择是二元的，McCormick 不等式会自动迫使配对变量精确取 0 或 1，无需额外声明为二元变量。

<!-- section:hint2 -->
在加入预算与人数上限约束后，为 $w_k = x_i x_j$ 施加精确的 McCormick 包络约束：两条上界（$w_k \le x_i$ 与 $w_k \le x_j$）防止在两名英雄未同时入队时开启 $w_k$，一条下界（$w_k \ge x_i + x_j - 1$）迫使两人同时入队时 $w_k = 1$。由于配对权重 $s$ 既可能为正（协同加成，缺少上界时求解器会虚增 $w_k$）也可能为负（互斥惩罚，缺少下界时求解器会压低 $w_k$），上下两个方向都不可或缺。返回整数结果时请对 `pairProducts` 进行取整。
