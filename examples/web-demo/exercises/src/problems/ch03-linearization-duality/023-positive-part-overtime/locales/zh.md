# #023. 正部惩罚线性化（多周期加班排班）

<!-- section:scenario -->
服务中心的运营管理员正在规划多个周期的常规工时（人时），以覆盖预测需求（人时）。

排班方案必须满足以下所有条件：
- **各周期上下限**：每个周期都设有合同规定的最低保底工时和设备产能上限。
- **总工时上限**：所有周期的常规工时总和不得超过总上限。
- **仅对缺口惩罚**：当某周期常规工时低于需求时，缺口部分需按每人时支付加班或外包惩罚（日元）；超出需求时既无退款也无额外收益。

请利用不等式线性表示缺口 $\max(0, \text{需求} - \text{常规工时})$，在满足所有条件的前提下，**最小化常规运营成本与加班惩罚之和（日元）**。

<!-- section:io -->
### 输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `demands` | `number[]` | 第 $t$ 周期的需求量 $d_t$（人时） |
| `minRegular` | `number[]` | 第 $t$ 周期的最低保底常规工时 $L_t$（人时） |
| `maxRegular` | `number[]` | 第 $t$ 周期的最大常规产能 $U_t$（人时） |
| `regularCosts` | `number[]` | 第 $t$ 周期的单位常规成本 $r_t$（日元/人时） |
| `overtimePenalties` | `number[]` | 缺口 $\max(0, d_t - x_t)$ 的单位加班惩罚 $p_t$（日元/人时） |
| `totalRegularCap` | `number` | 全周期常规工时总和 $\sum_t x_t$ 的上限（人时） |

### 输出

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `regular` | `number[]` | 各周期的常规工时 $x_t$（人时） |
| `shortage` | `number[]` | 各周期的缺口加班工时 $\max(0, d_t - x_t)$（人时） |
| `totalCost` | `number` | 最小化后的总成本（日元） |

<!-- section:example -->
**输入示例**

```json
{
  "demands": [40, 60, 50],
  "minRegular": [10, 10, 10],
  "maxRegular": [50, 50, 50],
  "regularCosts": [20, 25, 18],
  "overtimePenalties": [50, 45, 55],
  "totalRegularCap": 100
}
```

**输出示例**

```json
{
  "regular": [40, 10, 50],
  "shortage": [0, 50, 0],
  "totalCost": 4200
}
```

常规工时 [40, 10, 50] 合计 $100 \le 100$ 人时且满足各期上下界，缺口为 [0, 50, 0]，总成本为 $(20 \times 40 + 25 \times 10 + 18 \times 50) + (45 \times 50) =$ **4,200** 日元。


<!-- section:hint1 -->
为每个时期声明一个受限于最低保障水平和最大产能的连续常规产能变量，以及一个表示由加班弥补的未满足需求的非负连续缺口变量。

<!-- section:hint2 -->
要线性化单侧铰链函数 $\max(0, d_t - x_t)$，应使用不等式 $s_t \ge d_t - x_t$ 配合 $s_t \ge 0$，而不是等式——若使用等式，当常规产能因最低保障下限等原因超过需求时会迫使 $s_t < 0$ 而导致无解。还要注意符号方向（是 $d_t - x_t$ 而非 $x_t - d_t$），并别忘了所有时期常规产能总和的上限约束。由于加班惩罚为正且目标最小化总成本，最优解处每个 $s_t$ 会自动紧贴 $\max(0, d_t - x_t)$。
