# Z3 SMT 求解器引擎

**Z3** 是微软研究院开发的开源定理证明器与可满足性模理论（SMT）求解器。在 WaSHI 中，Z3 适用于包含 `Continuous` 变量或小数系数/常数的逻辑规则、精确算术判定以及 `unsatCore` 冲突诊断。

---

## 安装

`z3-solver` 是可选的 peer dependency：

```bash
npm install z3-solver
```

---

## 何时选择 Z3

| 目标 | 推荐求解器 | 原因 |
| :--- | :--- | :--- |
| **含 `Continuous` 或小数的逻辑规则** | **Z3**（`m.check({ solver: "z3" })`） | 在 `implies`、`not`、`and`、`or` 与 `xor` 中原生求值实数不等式。 |
| **含 `Continuous` 变量的冲突诊断** | **Z3**（`m.check({ solver: "z3" })`） | 在连续/整数混合模型中提取不受数值尺度影响的 `unsatCore`。 |
| **有界整数与布尔的约束规划** | **[Pumpkin](./pumpkin.md)** | 内置零依赖，无需配置跨域隔离响应头。 |
| **线性、混合整数或凸二次数值优化** | **[HiGHS](./highs.md)**（默认） | 内置单纯形法、内点法与分支切割法，目标函数数值优化速度更快。 |

> [!TIP]
> 常见做法是先用 **Z3** 的 `model.check()` 验证逻辑并定位冲突，再用 **HiGHS** 的 `model.solve()` 优化数值成本。

---

## 基本用法 (`model.solve()` 与 `model.check()`)

导入一次 `@ohtaman/washi/solvers/z3` 即可注册 `"z3"` 求解器。同一个 `Model` 支持两种运行模式：

- **`model.check()`**：在无目标函数的情况下检查可满足性，返回 `"Sat"`、`"Unsat"`（附带 `conflicts` / `unsatCore`）或 `"Unknown"`。
- **`model.solve()`**：使用 Z3 Optimize 优化线性目标函数。若未设置目标函数，则寻找任意可行赋值，可行时返回 `"Optimal"`（若在调用完成取得解时 `signal` 已被触发中止，则返回 `"Feasible"`）。

下面的示例为一个由布尔标志控制的连续变量阈值规则寻找可行解：

```typescript
import { Model, expr, implies } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });

const temp = model.continuous("temp", { lb: 0, ub: 100 });
const coolingOn = model.bool("cooling_on");

model.constraint(coolingOn, "enable_cooling");
model.constraint(implies(coolingOn, expr`${temp} <= 22.5`), "cooling_target");

// 未设置目标函数时，solve() 会寻找任意可行解。
// 若需 "Sat" / "Unsat" 状态及 unsatCore 诊断，请改用 model.check()。
await model.solve();
console.log(`Status: ${model.status}, temp = ${temp.value}`);
```

## 冲突诊断 (`model.check()`)

调用 `await model.check()` 可检查包含连续变量或整数变量（及混合）规则的可满足性。若状态为 `"Unsat"`，Z3 通过 `result.conflicts`（也可通过 `result.unsatCore` 和 `model.unsatCore` 读取）返回冲突命名约束子集：

```typescript
import { Model, expr } from "@ohtaman/washi";
import "@ohtaman/washi/solvers/z3";

const model = new Model({ solver: "z3" });
const a = model.continuous("a");

model.constraint(expr`${a} >= 10`, "req_A");
model.constraint(expr`${a} <= 5`, "req_B");

const result = await model.check();

if (result.status === "Unsat") {
  console.log("冲突约束:", result.conflicts);
  // ["req_A", "req_B"]
}
```

## 支持与不支持的选项

Z3 会严格校验选项和模型特性，传入不支持的内容时会直接抛出运行时 `Error`。

### 支持的选项

- `z3JsUrl` / `z3WasmUrl`：覆盖浏览器加载 `z3-built.js` 和 `z3-built.wasm` 的 URL（也可通过 `setZ3Assets()` 全局配置）。
- `signal`：仅在 Z3 开始求解**之前**检查中止状态（只支持求解前取消，无法中断正在进行的 Z3 调用）。
- `onProgress`：仅适用于 `solve()`（`check()` 会忽略）。在 `solve()` 完成后调用一次，报告耗时以及存在解时的最终目标值。

### 不支持的选项与特性（运行时抛出异常）

- **不支持的控制选项**：`timeLimit`、`relativeGap`、`absoluteGap`、`presolve`、`threads`、`verbose`、`outputFlag` 以及未知选项键会抛出 `Error`。
- **不支持的模式与特性**：`relax: true`、`useWorker: true`、`initialValue` 与 `QuadExpr` 会抛出 `Error`。

> [!NOTE]
> Z3 Optimize 是基于 SMT 的优化引擎，不提供 LP 灵敏度或分支定界对偶界：`c.dual`、`c.slack` 与 `v.reducedCost` 保持为 `null`，`objectiveBound`、`relativeGap` 与 `absoluteGap` 保持为 `undefined`。

## 浏览器要求与线程清理

在浏览器中，Z3 使用 `SharedArrayBuffer` 与 Emscripten pthread，页面必须满足以下两项前提条件：

1. **安全上下文（Secure Context）**：页面通过 `HTTPS` 或 `localhost` 提供服务。
2. **跨域隔离（`COOP`/`COEP`）**：文档响应头须包含 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp`。

服务器配置方法见[跨域隔离指南](../getting-started/cross-origin.md)。若无法配置这些响应头且模型仅包含有界整数和布尔变量，请改用 [Pumpkin](./pumpkin.md)。

如果 Z3 Worker 遇到致命错误，当前 Promise 会被 reject 并丢弃损坏的实例，下次调用会自动重新初始化。无论是 Node.js（让 CLI 脚本或进程正常退出）还是浏览器（例如卸载视图时），如需显式关闭 Z3 的 pthread 线程，请调用：

```typescript
import { killZ3Threads } from "@ohtaman/washi/solvers/z3";

await killZ3Threads();
```
